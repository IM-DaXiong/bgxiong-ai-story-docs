# 布局持久化（layout-persistence）跨重启排障与开发约束

> **适用范围**：`extensions.layoutStateV1` 下的 **分栏宽度**（`usePersistentSplit` / `usePersistentVerticalSplit`）、**弹层几何**（`useModal` / `AppModal`）、**折叠开关**、**textarea 边盒尺寸** 等。  
> **权威实现**：`ui/src/layout-persistence/`（内存 store + `AppSettingsContext` bridge + SQLite `app_user_settings`）。  
> **关联 BUG**：`FIX-BUG-20260521.md` **BUG-018～029**（弹层/分栏「重启后丢失」多轮定责终稿见 **029**）。

---

## 1. 典型现象（先对号入座，禁止瞎猜）

| 现象 | 常见误判（错） | 实际要查什么 |
|------|----------------|--------------|
| 同会话内拖拽分栏/弹层正常，**完全重启应用**后回到默认 | 「没 commit」「读错 layoutItemId」「SQLite 没写上」 | **先看日志对账**：`reload read layout`（磁盘） vs `MODAL_FRAME_PRELOAD` / 分栏实际 UI（内存 preload） |
| 关弹层后再开（不重启）正常，重启才丢 | 只查 `MODAL_FRAME_PERSIST commit` | commit 只证明**内存 store**；跨重启须 **`layout.flushExtensionsNow` + await** 且启动 preload 未被污染 |
| 弹层丢、侧栏丢、视频工作台三栏丢 **同时**出现 | 只修视频工作台 Host | **同一 `workspaceStates` Map**；根因多在 **启动时序**，不是某一业务模块 |
| 日志里 flush 已是自定义 w/h，preload 仍是 1080 | 「后端 set_app_user_settings 没写库」 | 可能是 **IPC 竞态覆盖**（028）或 **preload 用了污染内存**（029），须分两条线对账 |

**第一准则（本专题）**：凡「同会话 OK、重启丢失」，**禁止**在未对比 `reload read layout` 与 `MODAL_FRAME_PRELOAD`（及分栏相关字段）之前改业务代码或下结论。

## 2. 排障三步（日志 alone 应能定责）

### 步骤 A — 收集同一重启周期的前端日志

文件：`logs/frontend-YYYY-MM-DD.log`（与操作同日）。

### 步骤 B — 对账「磁盘 vs 内存 preload」

在同一新进程启动后 **300ms 内**应能看到：

| 顺序 | 日志键 / 前缀 | 含义 |
|------|----------------|------|
| ① | `[AppSettingsV4] reload read layout from SQLite` | 从 SQLite 解析出的 `videoWorkbenchFrame`（及 extensions 内 layout） |
| ② | `MODAL_FRAME_PRELOAD_VIDEO_WORKBENCH` | `preloadAllLayoutWorkspacesFromPersisted` 后 **内存 store** 中的弹层 frame，以及 `sidebarWidth`、`videoShellLeftWidth` |

**定责规则**：

- ① 为自定义值、② 仍为 catalog 默认 → **BUG-029 类（内存污染 / preload 未覆盖）**，不是「没写入 SQLite」。
- ① ② 均为默认 → 再查关窗/拖拽后是否有 `layout.flushExtensionsNow` 且 `videoWorkbenchFrame` 为自定义（028 类 IPC 竞态或未 flush）。
- ① ② 一致且为自定义，UI 仍默认 → 查 React 状态是否未 `setSize`（适配器 `useEffect` 同步）、或 `hydrate_fallback` 逻辑。

### 步骤 C — 确认落盘链（跨重启必需）

拖拽/关窗/分栏 pointerup 后，日志链应包含：

1. `layout.writeLayoutStates`（脏 workspace 合并进 extensions）
2. `layout.persistLayoutExtensionsNow` → `layout.flushExtensionsNow`
3. `videoWorkbenchFrame`（或对应 workspace 项）与 UI 一致

**禁止**仅凭 `MODAL_FRAME_PERSIST commit` 判定「已持久化跨重启」——commit 只更新 **内存 `workspaceStates`**。

## 3. 根因分类（开发经验归档）

### 3.1 启动时内存污染（BUG-029 · 分栏+弹层共性 · 高概率）

**机制**：

1. `AppSettings.loaded === false` 时，适配器曾在 **render 阶段**调用 `registerWorkspaceWithRestore`。
2. 此时 `registerLayoutStorageBridge` 未挂载 → `readLayoutState()` 为空 → 写入 **catalog 默认值**到 `workspaceStates`。
3. `preloadAllLayoutWorkspacesFromPersisted` 发现 workspace **已存在**，旧逻辑只补缺失 item，**不用磁盘覆盖**已有错误内存。
4. 同会话后续拖拽只改内存，故 **不重启看起来正常**；新进程重复 1～3，故 **重启全丢**。

**修复要点（已实现，勿回退）**：

- `preload` 前 `workspaceStates.clear()` + `registerWorkspaceWithRestore(..., { forceFromDisk: true })`。
- 适配器统一 `useLayoutWorkspaceRegister`（**仅 `loaded` 后 `useEffect` 注册**）。
- `reload` 完成时：**同步** `attachExtensionsBridges()` → `resetPreloadGuard()` → `preloadAllLayoutWorkspacesFromPersisted()` → `setLoaded(true)`。

### 3.2 extensions 整包 IPC 竞态（BUG-028）

**机制**：`queueExtensionsIpcPersist` 220ms debounce 的在途 `setAppUserSettings` 可在 `flushExtensionsNow` 之后完成，用**旧快照**覆盖 SQLite。

**修复要点**：`enqueueExtensionsPersist` Promise 链串行化；**禁止** Provider bridge teardown 整包写库。

### 3.3 关窗/杀进程未 await 落盘（BUG-024）

**机制**：`flushExtensionsNow` 未 await 或 `forceQuit` 过早 `exit(0)`。

**修复要点**：`flushExtensionsNow` 必须 await；关弹层 Host 在 `setIsOpen(false)` 后 `await flushAllDirtyAndPersistExtensionsNow`；`forceQuitApp` 短超时内尽力 flush（不挡关窗）。

### 3.4 业务层误伤（BUG-018/023）

- 关窗卸载 Modal 子树导致新 `useModal` 实例。
- `open()` 仅 `hasCustomSize` 才恢复，库内仍为 catalog 尺寸时走 `hydrate_fallback`。

与 **029** 正交：029 修好后若仍丢，再查 018/023/028。

## 4. 开发约束（新增/修改布局持久化代码时强制自检）

| # | 约束 |
|---|------|
| 1 | **禁止**在 `render` 中调用 `registerWorkspace` / `registerWorkspaceWithRestore`；须 `AppSettings.loaded === true` 后注册（`useLayoutWorkspaceRegister`）。 |
| 2 | **禁止**假设 `MODAL_FRAME_PERSIST commit` 等于跨重启持久化；跨重启以 `reload read layout` 与 preload 日志一致为准。 |
| 3 | 几何/分栏变更须在 pointerup / close / 必要时的 `flushAllDirtyAndPersistExtensionsNow` 路径 **await** 落盘。 |
| 4 | 新增 workspace 必须进 `workspaceCatalog.ts`（`LAYOUT_WORKSPACE_CATALOG`）；禁止散落 magic 默认值写进业务组件。 |
| 5 | 弹层 `layoutItemId` 须在 `modalFrameCatalog.ts` 的 `MODAL_FRAME_ITEMS` 注册；持久化键 `modal.app.frames` / `modal.shared.*`。 |
| 6 | **禁止**在 `AppSettingsProvider` bridge teardown 中 `setAppUserSettings` 整包写 extensions（StrictMode 竞态）。 |
| 7 | 验收必须含 **完全退出进程再启动**；仅「关 Tab 再开」不够。 |

## 5. 日志检索键速查

| 目标 | 检索 |
|------|------|
| 磁盘 layout（启动） | `[AppSettingsV4] reload read layout from SQLite` |
| 内存 preload（启动） | `MODAL_FRAME_PRELOAD_VIDEO_WORKBENCH` |
| 弹层 commit | `MODAL_FRAME_PERSIST` + `commit` |
| 弹层恢复 | `hydrate_restore` / `hydrate_fallback` |
| 写 extensions | `[SETTINGS_WRITE_IPC] layout.writeLayoutStates` |
| 立即落盘 | `layout.flushExtensionsNow` + `videoWorkbenchFrame` |
| 分栏 debounce 落盘 | `extensions-debounced` |

SQLite 路径：`app_user_settings` → `extensions` → `layoutStateV1` → `workspaces` → `<layoutId>` → `items` → `<itemId>` → `value`。

## 7. 经验一句话（给 Agent / 协作者）

> **同会话记住、重启全丢** → 先对比 **`reload read layout`（SQLite）** 与 **`MODAL_FRAME_PRELOAD`（内存）**；不一致就是 **启动污染内存**，不是「没记录拖拽」；分栏与弹层 **同一套 store**，不要只盯一个弹窗组件瞎改。
