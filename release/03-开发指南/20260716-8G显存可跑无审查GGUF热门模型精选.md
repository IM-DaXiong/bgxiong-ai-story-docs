**8GB 黄金量化规则**

- Dense **7B–9B**：优先 `Q4_K_M`（约 4.5–5.5GB 权重），留 2–3GB 给 KV cache / 上下文。
- 想更高质量且上下文不长（≤4K–8K）：可试 `Q5_K_M`。
- **12B+ dense** 全层上 GPU 很紧，通常要 `Q3` 或 CPU/GPU 混合卸载。
- **MoE 总参 18B+**：文件本身往往 >8GB，8G 卡多半只能「部分层上 GPU」。

**运行工具**：LM Studio / llama.cpp / KoboldCpp / Ollama（部分模型有 Ollama 标签）。

**本客户端（BigBear）最低 llama 运行时**

| 架构标签（GGUF） | 最低 llama.cpp | 客户端外挂运行时 version（Windows CUDA） |
|------------------|----------------|------------------------------------------|
| `gemma4`（Gemma 4 E4B / 12B 等） | **≥ b8635**（建议最新，如 b10038） | **≥ 20260716** |
| `qwen35` / 新 Qwen3.5 系 | 较新的 llama.cpp（随上游更新） | 建议与上同，保持外挂运行时最新 |

旧版 `20260621`（build 8569）会报 `unknown model architecture: 'gemma4'`。更新路径：设置 → 本地模型 → 外挂运行时 → llama → 下载/更新。

**免责声明**：无审查模型会显著降低拒绝率，可能输出敏感、违法或有害内容。仅建议用于本地研究与合规场景；生成内容法律责任由使用者自行承担。本文只做技术整理，不鼓励非法用途。

## 1. 什么叫「无审查」GGUF？

社区常见两类：

1. **Fine-tune Uncensored**（如 Dolphin、WizardLM Uncensored）  
   训练数据刻意去掉对齐/拒绝样本，行为更可控、风格更稳定。
2. **Abliterated / Heretic**（如 mlabonne abliteration、Heretic ARA）  
   用数学方法削弱「拒绝方向」权重，尽量少伤原模型能力（看 KL divergence / refusal 评测）。

GGUF = llama.cpp 生态通用量化格式，一份 `.gguf` 即可本地推理。

## 5. 8G 实战参数建议

| 设置 | 建议 |
|------|------|
| 量化 | 7B–9B → `Q4_K_M` 默认；质量优先 → `Q5_K_M` + ctx≤8K |
| Context | 先 4096 / 8192；爆显存先砍 ctx，再砍量化 |
| GPU layers | 尽量全层；OOM 时减 2–4 层到内存 |
| Flash Attention | 新版 llama.cpp / LM Studio 尽量开启 |
| Temperature | 创意写作 0.8–1.2；代码/分析 0.2–0.6 |
| 中文 | 优先 Qwen3.5 / Qwythos；Llama 系也可但中文弱一档 |

粗算：

```
可用权重预算 ≈ 8GB - 1.5~2.5GB（驱动+KV+运行时）
             ≈ 5.5~6.5GB
→ 8B Q5 或 9B Q4 通常刚好；再开长上下文就会顶满。
```
