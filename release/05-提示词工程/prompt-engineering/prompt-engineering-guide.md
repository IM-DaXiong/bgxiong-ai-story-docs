## 核心概念

### 什么是提示工程？
提示工程（Prompt Engineering）是设计和优化提示词以从 AI 模型获得最佳输出的实践。它结合了语言理解、任务分析和创造性思维。

### 为什么重要？
- 提高输出质量
- 减少迭代次数
- 获得更一致的结果
- 节省时间和成本

## 基础技术

### 1. 零样本提示（Zero-shot Prompting）

**定义**：不提供任何示例，直接描述任务。

**示例**：
```
请将以下文本分类为正面或负面情感：
"这部电影太棒了！"
```

**适用场景**：
- 简单、明确的任务
- 模型已有相关知识
- 快速原型设计

**优点**：
- 简单快捷
- 不需要准备示例
- 适合通用任务

**缺点**：
- 对复杂任务效果有限
- 输出格式可能不一致
- 需要更精确的描述

### 2. 少样本提示（Few-shot Prompting）

**定义**：提供少量示例来引导模型。

**示例**：
```
将以下文本分类为正面或负面情感：

文本：今天天气真好！
情感：正面

文本：这部电影太无聊了。
情感：负面

文本：这个产品太棒了！
情感：
```

**适用场景**：
- 需要特定格式或风格
- 复杂分类任务
- 领域特定任务

**优点**：
- 更一致的输出格式
- 更好的任务理解
- 适合专业领域

**缺点**：
- 需要准备示例
- 增加提示词长度
- 示例质量影响结果

### 3. 思维链提示（Chain-of-thought Prompting）

**定义**：引导模型展示推理过程。

**示例**：
```
请一步一步思考：

问题：小明有 5 个苹果，给了小红 2 个，又买了 3 个，现在有多少个？

思考过程：
1. 小明开始有 5 个苹果
2. 给了小红 2 个，剩下 5 - 2 = 3 个
3. 又买了 3 个，现在有 3 + 3 = 6 个

答案：6 个
```

**适用场景**：
- 数学问题
- 逻辑推理
- 复杂决策
- 需要解释的任务

**优点**：
- 提高准确性
- 更好的可解释性
- 减少错误

**缺点**：
- 增加输出长度
- 可能过度推理
- 需要更多计算资源

### 4. 自一致性（Self-consistency）

**定义**：多次运行同一提示词，选择最一致的答案。

**流程**：
1. 使用相同提示词多次查询
2. 收集所有输出
3. 分析最常出现的答案
4. 选择最一致的结果

**适用场景**：
- 高风险决策
- 需要高可靠性
- 关键业务应用

**优点**：
- 提高可靠性
- 减少随机错误
- 更可预测的结果

**缺点**：
- 增加成本
- 需要多次调用
- 可能过度保守

### 5. 检索增强生成（RAG）

**定义**：结合外部知识库提供更准确的信息。

**示例**：
```
基于以下文档回答问题：

文档：[相关文档内容]

问题：[用户问题]

请基于文档内容回答，如果文档中没有相关信息，请说明。
```

**适用场景**：
- 需要最新信息
- 领域特定知识
- 事实核查
- 知识密集型任务

**优点**：
- 提供最新信息
- 减少幻觉
- 可追溯来源
- 知识可更新

**缺点**：
- 需要维护知识库
- 增加系统复杂性
- 检索质量影响结果

## 设计原则

### 1. 明确性（Clarity）

**原则**：清晰描述任务，避免歧义。

**技巧**：
- 使用具体动词（如"分析"、"总结"、"比较"）
- 避免模糊词汇（如"好的"、"合适的"）
- 提供明确的边界条件

**示例**：
```
❌ 模糊：帮我写点东西
✅ 明确：写一篇 500 字的产品描述，突出其三大核心优势
```

### 2. 具体性（Specificity）

**原则**：提供足够的细节和约束。

**技巧**：
- 指定输出格式
- 定义长度限制
- 说明目标受众
- 提供评价标准

**示例**：
```
❌ 笼统：写一篇文章
✅ 具体：写一篇面向初学者的 Python 教程，包含代码示例，长度 1000 字
```

### 3. 结构化（Structure）

**原则**：使用清晰的组织结构。

**技巧**：
- 使用分隔符（---、"""、###）
- 分步骤描述
- 使用列表和编号
- 添加标题和子标题

**示例**：
```
请按以下结构完成任务：

## 第一部分：分析
分析给定数据的关键特征

## 第二部分：总结
总结主要发现

## 第三部分：建议
基于分析提出建议
```

### 4. 迭代优化（Iteration）

**原则**：通过测试和反馈持续改进。

**流程**：
1. 创建初始提示词
2. 测试输出效果
3. 分析问题和不足
4. 调整和优化
5. 重复直到满意

**技巧**：
- 记录每次修改
- 对比不同版本
- 收集用户反馈
- 建立最佳实践库

## 高级技巧

### 1. 角色设定（Role Setting）

**定义**：为 AI 设定特定角色。

**示例**：
```
你是一位经验丰富的软件工程师，擅长 Python 和系统设计。
请以这个角色回答我的问题。
```

**效果**：
- 获得专业视角
- 更相关的建议
- 更一致的风格

### 2. 任务分解（Task Decomposition）

**定义**：将复杂任务分解为小步骤。

**示例**：
```
请按以下步骤完成任务：
1. 分析需求
2. 设计方案
3. 编写代码
4. 测试验证
5. 编写文档
```

**效果**：
- 更好的组织性
- 减少遗漏
- 更容易验证

### 3. 输出格式控制

**定义**：明确指定输出格式。

**示例**：
```
请以 JSON 格式输出：
{
  "summary": "摘要",
  "key_points": ["要点1", "要点2"],
  "recommendations": ["建议1", "建议2"]
}
```

**效果**：
- 一致的输出格式
- 易于程序处理
- 减少后处理

### 4. 约束条件设置

**定义**：设定明确的限制和要求。

**示例**：
```
注意：
- 回答不超过 200 字
- 使用中文
- 保持专业语气
- 避免技术术语
```

**效果**：
- 控制输出范围
- 满足特定需求
- 提高可用性

### 5. 示例驱动（Example-driven）

**定义**：通过示例展示期望的输出。

**示例**：
```
请按照以下示例的风格写作：

示例：
"这款产品采用了先进的 AI 技术，为用户提供了前所未有的体验。"

现在请写一段类似风格的产品描述。
```

**效果**：
- 更一致的风格
- 更好的理解
- 减少误解

## 常见模式

### 1. 分析模式
```
请分析以下内容：
1. 背景信息
2. 关键问题
3. 影响因素
4. 可能的解决方案
5. 推荐方案
```

### 2. 创作模式
```
请创作一篇关于 [主题] 的文章：
- 风格：[指定风格]
- 长度：[指定长度]
- 受众：[目标读者]
- 结构：[指定结构]
```

### 3. 转换模式
```
请将以下内容转换为 [目标格式]：
- 保持核心信息不变
- 调整语言风格
- 优化可读性
```

### 4. 评估模式
```
请评估以下内容：
- 优点
- 缺点
- 改进建议
- 总体评分（1-10）
```

### 5. 对话模式
```
让我们进行一场关于 [主题] 的对话：
- 你扮演 [角色]
- 我扮演 [角色]
- 场景设定：[描述场景]
```

## 最佳实践

### DO（推荐做法）

1. **明确目标**
   - 清楚说明你想要什么
   - 提供足够的上下文
   - 设定期望的输出格式

2. **提供示例**
   - 展示期望的输出
   - 说明风格和语气
   - 演示格式要求

3. **使用结构**
   - 分步骤描述
   - 使用标题和列表
   - 添加分隔符

4. **设定约束**
   - 明确长度限制
   - 指定语言和风格
   - 定义边界条件

5. **迭代优化**
   - 测试不同版本
   - 收集反馈
   - 持续改进

### DON'T（避免做法）

1. **避免模糊**
   - ❌ "写点好东西"
   - ✅ "写一篇 500 字的产品优势分析"

2. **避免歧义**
   - ❌ "处理这个"
   - ✅ "分析数据并生成可视化图表"

3. **避免过度复杂**
   - ❌ 一次性要求太多
   - ✅ 分步骤完成

4. **避免假设**
   - ❌ 假设 AI 知道你的意图
   - ✅ 明确说明所有要求

5. **避免忽略反馈**
   - ❌ 忽视输出质量问题
   - ✅ 根据结果调整提示词

## 调试技巧

### 1. 问题诊断

**症状**：输出不符合预期
**检查**：
- 提示词是否清晰？
- 是否提供了足够示例？
- 约束条件是否明确？

**症状**：输出格式混乱
**检查**：
- 是否指定了输出格式？
- 示例是否展示了正确格式？
- 是否使用了结构化描述？

**症状**：输出内容错误
**检查**：
- 任务描述是否准确？
- 是否提供了必要上下文？
- 是否有歧义或误导？

### 2. 优化策略

**策略**：简化提示词
- 移除不必要的细节
- 聚焦核心任务
- 使用更直接的语言

**策略**：增加示例
- 添加更多示例
- 展示边缘情况
- 说明期望输出

**策略**：调整结构
- 重新组织提示词
- 使用更清晰的格式
- 添加分隔符和标题

**策略**：迭代测试
- 小步调整
- 记录每次修改
- 对比不同版本

## 总结

提示工程是一门结合技术理解和创造性思维的实践。通过掌握基础技术、遵循设计原则、运用高级技巧，并持续迭代优化，你可以显著提高 AI 输出的质量和一致性。

记住：
1. **明确性**比创意更重要
2. **示例**是最好的老师
3. **迭代**是成功的关键
4. **实践**出真知
