## 核心技术

### 1. 零样本提示（Zero-shot Prompting）
```
请将以下文本分类为正面或负面情感：
"这部电影太棒了！"
```
- 不提供示例，直接描述任务
- 适用于简单、明确的任务

### 2. 少样本提示（Few-shot Prompting）
```
将以下文本分类为正面或负面情感：

文本：今天天气真好！
情感：正面

文本：这部电影太无聊了。
情感：负面

文本：这个产品太棒了！
情感：
```
- 提供少量示例引导模型
- 适用于需要特定格式或风格的任务

### 3. 思维链提示（Chain-of-thought Prompting）
```
请一步一步思考：

问题：小明有 5 个苹果，给了小红 2 个，又买了 3 个，现在有多少个？

思考过程：
1. 小明开始有 5 个苹果
2. 给了小红 2 个，剩下 5 - 2 = 3 个
3. 又买了 3 个，现在有 3 + 3 = 6 个

答案：6 个
```
- 引导模型展示推理过程
- 提高复杂问题的准确性

### 4. 自一致性（Self-consistency）
- 多次运行同一提示词
- 选择最一致的答案
- 提高可靠性

### 5. RAG（检索增强生成）
```
基于以下文档回答问题：

文档：[相关文档内容]

问题：[用户问题]
```
- 结合外部知识库
- 提供更准确、最新的信息

## 提示词设计原则

### 1. 明确性（Clarity）
- 清晰描述任务
- 避免歧义
- 使用具体指令

### 2. 具体性（Specificity）
- 指定输出格式
- 定义约束条件
- 提供示例

### 3. 结构化（Structure）
- 使用分隔符（---、"""、###）
- 分步骤描述
- 使用列表和编号

### 4. 迭代优化（Iteration）
- 测试不同版本
- 收集反馈
- 持续改进

## 常用技巧

### 角色设定
```
你是一位经验丰富的软件工程师，擅长 Python 和系统设计。
```

### 任务分解
```
请按以下步骤完成任务：
1. 分析需求
2. 设计方案
3. 编写代码
4. 测试验证
```

### 输出格式
```
请以 JSON 格式输出：
{
  "summary": "摘要",
  "key_points": ["要点1", "要点2"],
  "recommendations": ["建议1", "建议2"]
}
```

### 约束条件
```
注意：
- 回答不超过 200 字
- 使用中文
- 保持专业 tone
```
