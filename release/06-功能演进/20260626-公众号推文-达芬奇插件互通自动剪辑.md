## 一、比格熊是什么？

**比格熊数字导演工作站**是一套 AI 驱动的多模态故事与分镜工作台，产品形态是安装在电脑上的**桌面客户端软件**（基于 Tauri 2 + Rust + React）。

它的核心理念是：**用 AI 将"一句话故事"自动拆解为完整的可视化制作管线**——从故事种子到剧集、场次、镜头、分镜图、视频成片，全链路自动化。

但今天我们不展开讲它的全部能力（故事生成、分镜引擎、角色管理、AI 视频生成……这些以后慢慢聊），我们聚焦在一个**立刻能用、立刻提效**的杀手功能上：

## 二、架构总览：客户端与插件如何互通？

### 2.1 本地桥接（Local Bridge）

比格熊客户端与达芬奇插件之间，通过一套名为 **Local Bridge（本地桥接）** 的传输层进行通信。

```
┌──────────────────────┐          ┌──────────────────────────┐
│  比格熊桌面客户端      │  HTTP+SSE │  达芬奇 Resolve 插件       │
│  (Transport Host)    │◄────────►│  (Transport Client)      │
│                      │          │                          │
│  • Whisper 语音识别   │          │  • 发起自动剪辑请求         │
│  • AI 分析 + FCPXML   │          │  • 接收 FCPXML            │
│  • 本地 SQLite + 文件  │          │  • ImportTimelineFromFile │
└──────────────────────┘          └──────────────────────────┘
```

**关键技术特点：**

- **零侵入设计**：默认关闭，不改变达芬奇原有行为，只在用户主动触发时才工作
- **本地通信**：仅监听 `127.0.0.1`，不对外暴露端口，数据不出本机
- **信封协议**：所有消息使用统一的 `BridgeEnvelope` 格式（`messageType` + `correlationId` + `payload`），支持同步 RPC、异步推送、轮询三种通信模式
- **自动发现**：插件通过 `%LOCALAPPDATA%/BigBear/local-bridge/registry.json` 自动发现客户端端口
- **路径安全**：`path_policy` 限制文件访问范围，只允许安全目录下的文件引用

### 2.2 三种通信模式

| 模式 | 方向 | 用途 | 举例 |
|------|------|------|------|
| **A. Sync-RPC** | 插件→客户端 | 请求-响应 | 发起语音识别、自动剪辑 |
| **B. Async-Outbound** | 客户端→插件 | 进度推送 | 识别进度、处理状态 |
| **C. Story-Push** | 客户端→插件 | 结果推送 | FCPXML 生成完毕，通知插件取件 |

## 三、自动剪辑管线：Speech Mark First（SMF v4）

这是当前最新的自动剪辑架构（2026-06-24 落地），设计理念是**化繁为简**：

### 3.1 旧方案的问题

早期的自动剪辑方案走的是"物理去静音"路线——用 ffmpeg 检测静音段、切掉、再把有用的部分拼接成一条母带，然后在母带上做语音识别。这个方案有几个致命问题：

- **双时间线坐标**：母带时间 ≠ 原始素材时间，来回映射容易出错
- **拼接点静音**：多段素材拼接处可能产生新的静音
- **4000+ 行补偿代码**：在插件侧用 `AppendToTimeline` 逐段添加子片段，需要大量补偿逻辑处理时间偏移

### 3.2 新方案的核心思想

**不做物理切割，直接在原始素材上做语音标记。**

```
原始素材（多文件）
    │
    ▼
Whisper 语音识别（逐文件，原始坐标）
    │
    ▼
语音块构建（合并相邻段、过滤超短句、尾切静音）
    │
    ▼
[可选] AI 大模型精炼（去重、语气词、重复句分类）
    │
    ▼
生成 FCPXML（直接引用原始媒体 URL，使用源坐标）
    │
    ▼
达芬奇 ImportTimelineFromFile（一键导入）
```

**关键优势：**

1. **单一时间线坐标**：始终使用原始素材的时间坐标，无需映射
2. **不做物理切割**：不对视频文件做任何修改，FCPXML 直接引用原始文件
3. **Whisper 边界即语音边界**：用 AI 语音识别的分段时间戳定义保留区间，比能量检测更智能
4. **150ms 尾 padding**：每段语音末尾自动保留 150ms 余量，避免尾音被切
5. **AI 大模型可选**：默认关闭，需要时才用 LLM 做去重和语气词分类，不强制

### 3.3 单端点 API

整个流程简化为一个接口：

```
POST /v1/speech/mark
{
  "mediaPaths": ["D:/素材/口播1.mp4", "D:/素材/口播2.mp4"],
  "language": "zh",
  "enableLlmRefine": false,
  "tailPaddingMs": 150
}
```

客户端异步处理后，通过 outbox 推送结果（含 FCPXML 路径和 SHA256），插件取件后导入达芬奇。

## 四、具体使用方法

### 4.1 安装准备

**第一步：安装比格熊客户端**

下载并安装比格熊数字导演工作站桌面客户端（Windows）。

**第二步：安装达芬奇插件**

将 BigBear 插件放入达芬奇 Workflow Integration Plugins 目录：

```
C:\ProgramData\Blackmagic Design\DaVinci Resolve\Support\Workflow Integration Plugins\BigBear
```

**第三步：启动客户端**

启动比格熊客户端后，本地桥接服务自动在 `127.0.0.1:39281-39289` 范围内启动，并在注册表中写入发现信息。

### 4.2 三种使用方式

#### 方式一：达芬奇插件内发起（推荐）

1. 在达芬奇中打开你的项目
2. 在 BigBear 插件面板中，点击 **"自动剪辑"**
3. 选择需要处理的素材文件（支持多文件同时处理）
4. 选择语言（中文/英文等）
5. 可选：开启"AI 大模型精炼"（会调用 LLM 对识别结果做去重和分类）
6. 点击 **"开始分析"**

插件通过本地桥接将请求发送给比格熊客户端，客户端开始处理：

- **Phase 1**：Whisper 本地语音识别（逐文件、逐段标记）
- **Phase 2**：语音块构建（合并相邻段、超短句过滤、尾切）
- **Phase 3（可选）**：AI 大模型精炼
- **Phase 4**：生成 FCPXML

处理完成后，FCPXML 自动推送到达芬奇，插件调用 `ImportTimelineFromFile` 导入时间线。

#### 方式二：客户端 App 内发起

1. 在比格熊客户端中打开 **自动剪辑弹窗**（AutoCutModal）
2. 选择素材文件
3. 配置参数后点击"开始"
4. 处理完成后，可选择 **"推送到达芬奇插件"**
5. 达芬奇插件收到推送后自动导入

#### 方式三：从已有字幕生成（Scene B）

如果你已经有字幕文件（SRT 等），可以跳过语音识别步骤：

1. 在自动剪辑弹窗中选择 **"Scene B（基于已有字幕）"** 模式
2. 导入字幕文件
3. AI 大模型分析字幕内容，自动去重、去废话、识别有效片段
4. 生成 FCPXML → 推送达芬奇

## 五、核心能力一览

### 5.1 智能语音切分

| 能力 | 说明 |
|------|------|
| **多文件并行处理** | 支持同时处理多个素材文件，各自独立识别 |
| **Whisper 本地识别** | 语音识别完全在本地运行，无需联网，数据不出本机 |
| **超短句过滤** | 自动过滤时长过短的无意义片段 |
| **尾切静音** | 每段语音末尾自动裁剪多余静音，保留 150ms 自然过渡 |
| **跨文件边界处理** | 多文件场景下正确处理边界，不会在文件切换处产生碎片 |

### 5.2 AI 大模型精炼（可选）

开启后，AI 会对 Whisper 识别结果进行进一步分析：

- **去重**：识别并标记重复的句子（口播中常见的"再讲一遍"）
- **语气词分类**：区分有效内容和填充词（"嗯"、"那个"等）
- **语义分段**：基于内容语义进行更合理的段落划分
- **不改时间戳**：LLM 只做分类标记，不修改 Whisper 给出的时间边界，避免 AI 幻觉导致的坐标错误

### 5.3 FCPXML 导出与达芬奇导入

- **声明式导入**：使用达芬奇的 `ImportTimelineFromFile` API，一次性导入完整时间线，而非逐段 `AppendToTimeline`
- **原始坐标引用**：FCPXML 直接引用原始媒体文件的 URL，时间坐标为源文件坐标，达芬奇可直接定位
- **SHA256 去重**：每次推送附带 FCPXML 的 SHA256 哈希，插件侧自动判断是否已导入，避免重复

### 5.4 进度追踪

整个处理过程实时反馈进度：

- 语音识别进度（当前文件 / 总文件数）
- 每段素材的处理状态
- FCPXML 生成完成通知
- 达芬奇导入结果反馈

## 六、技术亮点

### 6.1 真正的本地优先

所有语音识别和 AI 处理都在**你的电脑上**完成：

- Whisper 模型本地运行，无需上传音频到任何云端服务
- 可选 LLM 精炼走的是你已经在比格熊设置中配置好的 AI 模型
- 素材文件全程不出本机，隐私安全有保障

### 6.2 不绑定单一工作流

你可以自由选择：

- **全自动**：素材 → 自动剪辑 → FCPXML → 达芬奇（一键完成）
- **半自动**：先做语音识别，人工审核字幕，再生成剪辑
- **手动参考**：只做语音识别，拿到时间戳后手动剪辑

### 6.3 架构可扩展

本地桥接的信封协议不止用于自动剪辑，还支持：

- **高光切片**（highlight）：AI 分析视频内容，自动提取精彩片段
- **字幕识别**（subtitle.recognize）：纯语音转字幕
- **语音裁剪**（speech trim）：基于字幕时间码的语音块分割
- **母带预处理**：ffmpeg 去静音 + GPU 加速母带合并

## 八、常见问题

**Q：需要联网吗？**
A：语音识别完全本地运行（Whisper），无需联网。如果开启 AI 大模型精炼，需要访问你配置的 AI 服务（云端或本地 llama.cpp 均可）。

**Q：支持哪些语言？**
A：Whisper 支持的语言都支持，包括中文、英文、日文、韩文等。推荐中文和英文，效果最佳。

**Q：处理速度如何？**
A：取决于你的硬件配置和素材时长。以 NVIDIA RTX 3060 + Whisper large-v3 为例，1 小时中文口播约需 3-5 分钟完成识别。

**Q：FCPXML 导入达芬奇后还需要手动调整吗？**
A：自动剪辑的目标是**粗剪**——把素材中的有效对话提取出来、去掉明显废段。导入后的时间线已经是一个可用的粗剪版本，你只需要做最后的精修和润色，不需要再从头拖时间线。

**Q：插件支持哪些版本的达芬奇？**
A：达芬奇 Resolve 18+（含免费版），通过 Workflow Integration 插件机制接入。
