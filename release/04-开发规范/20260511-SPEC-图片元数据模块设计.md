## 1. 目标与非目标

### 1.1 目标

提供 **单一 Tauri 命令** `get_image_metadata`，在已知 **`nodeId` + `versionId` + `imageId`** 的前提下，从 SQLite `nodes` 与对应 JSON 版本列解析并返回 **camelCase** 的 `ImageMetadata`，供前端右键「查看元数据」展示。

返回字段至少包含：

- 展示用名称（组装标题）、所属节点类型语义（见 `ownerType`）、节点展示名
- `localCachePath`（`app_data_dir` 相对路径）、拼接得到的绝对路径 `realPath`
- 该张图对应的 **`fullPrompt`（落库字段名，IPC 输出键 `finalPrompt`）**
- 版本级元数据：`timestamp`（毫秒）、`provider`、`styleDomain`、`shotScale` 等（按数据源尽力填充）

### 1.2 非目标（本规格不要求首期实现）

- **故事板画布节点**：最终提示词可能在 `storyboard_graph_state` / 节点 `content` 分段（`---FINAL_PROMPT---`）中，**不走 `portrait_versions` / `scene_versions`**。首期不接右键元数据；若产品要强需求，另起 SPEC（需读取 graph 或 segment content）。
- **仅持有 HTTP URL / 历史 b64、无 `localCachePath` 的旧数据**：仍返回 `finalPrompt` 等；`realPath` 可为 `null`，不在此规格强制修复历史数据。
- **自动生成英文错误码**：沿用仓库惯例 `Result<T, String>` 即可；字符串需稳定、可检索（建议前缀，见 §7）。

## 3. `ownerType` 语义与判定（权威）

IPC 枚举 **`ImageOwnerType`**（serde `snake_case`，TS 联合字面量一致）：

| `ownerType` | 含义 |
|-------------|------|
| `actor` | 演员节点 **`nodes.node_type = 'actor'`** 下的 **四视角肖像**（每张图通常含 `direction`；版本来自 `portrait_versions`） |
| `cast_portrait` | 演员节点下 **剧集角色静帧**（`cast_portrait_still_pipeline` 写入）；与 `actor` 共用 `portrait_versions`，**必须用图像 id 区分** |
| `role` | 角色节点 `role` |
| `segment` | 片段节点 `segment` |
| `scene` | 场次场景节点 `scene` |
| `scene_asset` | 场景资产节点 `scene_asset` |

### 3.1 判定流程（必须按此实现）

```
输入 nodeId, versionId, imageId
  → 读 nodes.node_type（不存在则 Err）
  → 按 node_type 选择 JSON 数据源：
        actor | role | segment  → portrait_versions_sql::read_portrait_versions
        scene | scene_asset      → scene_versions_sql::read_scene_versions
      其它 node_type             → Err（明确列出支持的类型）
  → 在数组中定位 versionId，再定位 imageId
  → ownerType 基础值：
        role → role
        segment → segment
        scene → scene
        scene_asset → scene_asset
        actor → 若 imageId 以 "-still" 结尾 → cast_portrait，否则 → actor
```

**依据**：`cast_portrait_still_pipeline` 写入的图片 id 为 `{version_uuid}-still`；演员四视角为 `{version_uuid}-{direction}`（参见 `cast_portrait_still_pipeline.rs` / `actor_portrait_pipeline.rs`）。

### 3.2 禁止的做法

- **禁止**依赖 `nodes.node_type == 'cast_portrait'`（不存在该类型）。
- **禁止**仅用 `version.portraitSubject === "actor"` 区分四视角与静帧（两者均可为 `actor`）。

## 4. 数据源与 JSON 字段

### 4.1 列映射

| `node_type` | SQLite JSON 列 | 读取 API |
|-------------|----------------|----------|
| `actor`, `role`, `segment` | `nodes.portrait_versions` | `portrait_versions_sql::read_portrait_versions` |
| `scene`, `scene_asset` | `nodes.scene_versions` | `scene_versions_sql::read_scene_versions` |

### 4.2 版本对象（数组元素）

常见字段（**.camelCase 与落库一致**，读取时用 serde_json `Value` 即可）：

| 字段 | 说明 |
|------|------|
| `id` | 版本 UUID |
| `ts` | 时间戳；**约定毫秒**（见 §5） |
| `provider` | 生成通道 |
| `styleDomain` | `realistic` / `anime` 等 |
| `shotScale` | 景别；历史数据可能非 canonical，前端可用 `shotScaleLabelKey` 等既有工具美化 |
| `portraitSubject` | 辅助字段，**不作为** `cast_portrait` 判别主依据 |
| `images` | 图片数组 |

### 4.3 图片对象（`images[]`）

| 字段 | 说明 |
|------|------|
| `id` | 图片 id（与命令入参 `imageId` 对应） |
| `localCachePath` | 相对 `app_data_dir`；缺失则 `realPath` 为空 |
| `fullPrompt` | **最终提示词**；IPC 映射为 `finalPrompt` |
| `direction` | 可选，`front` / `back` / `left` / `right`（四视角） |

### 4.4 `ownerName`（节点展示名）

与现有 `commands/node.rs` 中 **`extract_actor_name_from_content`** 等行为 **对齐**：优先解析 JSON 的 `name`，否则截取纯文本前缀；避免在本命令重复发明另一套解析规则。若后续提取逻辑抽到 `node::` 公共函数，本命令应 **调用同一函数**，防止分叉。

## 5. 时间戳规范

- **对外字段**：`ImageMetadata.timestamp` 一律为 **Unix 毫秒**。
- **实现**：优先取版本对象 `ts`。若发现数值 `< 1_000_000_000_000`（明显为秒），可乘 `1000` 归一化为毫秒（兼容潜在历史异常）；否则直接使用。

---

## 6. 路径与「路径安全」表述

- `localCachePath`：数据库内存储的相对路径（严格模式，见肖像管线）。
- `realPath`：`paths::app_data_dir().join(rel)` 规范化后的绝对路径字符串；若 `localCachePath` 为空则 `null`。
- 说明：绝对路径仍会暴露本机目录结构；所谓安全是指 **路径限定在应用数据根目录内拼接**，不随意读取任意磁盘路径。

## 7. 错误信息、日志与命令签名

### 7.1 命令签名（建议同步函数）

与多数 `commands::` 一致，使用 **`State<DbState>` + 同步 `pub fn`**（解析 JSON 量级轻，无需强行 `async`）：

```rust
#[tauri::command(rename_all = "camelCase")]
pub fn get_image_metadata(
    db: tauri::State<'_, crate::db::DbState>,
    node_id: String,
    version_id: String,
    image_id: String,
) -> Result<ImageMetadata, String>
```

参数名 IPC camelCase：`nodeId`, `versionId`, `imageId`。

### 7.2 错误字符串（稳定、可读）

建议固定前缀，便于 grep：

- `IMAGE_METADATA: node not found`
- `IMAGE_METADATA: unsupported node_type=...`
- `IMAGE_METADATA: portrait_versions missing or corrupt`
- `IMAGE_METADATA: version not found`
- `IMAGE_METADATA: image not found`

### 7.3 日志

入口打一行：`tracing::info!(node_id=%..., version_id=%..., image_id=%..., "IMAGE_METADATA: query");`  
错误分支 `warn!` 带同上 correlation。**禁止**在日志中输出完整 `finalPrompt` 以外的密钥类字段（通常无）。

## 8. Rust 类型草案（与仓库 serde 惯例一致）

文件：`src-tauri/src/commands/image/commands/metadata.rs`（须含仓库强制 **中文文件头注释**）。

要点：

- `ImageOwnerType`：`#[serde(rename_all = "snake_case")]`。
- `ImageMetadata`：`#[serde(rename_all = "camelCase")]`；Rust 字段仍 `snake_case`（`image_id` → `imageId`）。
- `real_path` / `local_cache_path`：`Option<String>`。
- `final_prompt`：`String`，缺省时 `""` 还是 `Err` —— **首期允许空串**，便于展示导入占位图；若产品要求强制有提示词再改为 Err。

`build_image_name`（中文片段）仅用于 **`image_name` 展示**，可与前端 i18n 并存；后续若统一英文化，再改为键或通过前端组装。

### 9.2 `invoke` 封装

```typescript
import { invoke } from "@tauri-apps/api/core";
import type { ImageMetadata } from "./types";

export async function getImageMetadata(
  nodeId: string,
  versionId: string,
  imageId: string,

  return invoke<ImageMetadata>("get_image_metadata", { nodeId, versionId, imageId });
```

实际放置位置：与现有 `api/methods/apiPart3.ts` 等风格一致（若项目已有统一 `api` 对象，则挂到同一对象上）。

### 9.3 `styleDomain` 展示

避免 `anime ? 动漫 : 真人` 二元误判：未知取值显示 **原始字符串** 或走 i18n map。

## 10. 接入点与取参约定（关键）

右键菜单触发时必须传入 **用户正在操作的那一张图** 的 `versionId` / `imageId`，而不是随意猜「最新一张」。

| 接入组件（规格列举） | 取参建议 |
|---------------------|----------|
| `SceneTabGroupedSceneList.tsx` | 场景节点：从当前缩略图绑定对象取 `scene` 的 `nodeId` + 该图在 `scene_versions` 中的 version/image id（若列表组件仅有合并 URL，需向下传入 id） |
| `ShotCard.tsx` | 分镜卡片：`item.id` 为 **片段节点 id**；`portraitVersions` JSON 内解析当前帧对应 `versionId`/`imageId`（与 `useNodePortraitPreviewUrl` 所用数据同源） |
| `PadCanvasTile.tsx` | 参考图瓦片：瓦片渲染时应持有绑定的 `nodeId` + `versionId` + `imageId` |
| `SceneAssetListContextMenu.tsx` | 场景资产节点 + 对应 `scene_versions` 引用 |
| `RoleDetailPanel.tsx` | 角色节点 `role` + `portrait_versions` |

**与预览逻辑对齐**：`characterPortraitVersions.ts` 中 **`loadPortraitDefault` / 列表最后一帧** 的逻辑决定「当前显示的是哪张图」；右键「查看元数据」应对 **当前右键目标图** 传参。若某处 UI 仅有 blob/url 而无 id，需先在数据层补齐 id（本规格要求）。

## 11. 性能说明

- 单次调用：常数级 SQLite 读取 + 一次 JSON 反序列化（整列 `portrait_versions` / `scene_versions`），与现有列表加载同量级；不在此规格强制分页。
- 说明纠正：并非「零 DB 查询」——至少读取节点元数据 + 版本列。

## 12. 测试与验收

| 用例 | 预期 |
|------|------|
| 演员四视角某一帧 | `ownerType=actor`，`direction` 有值，`finalPrompt` 非空（若管线写过） |
| 演员静帧 `-still` | `ownerType=cast_portrait`，无 `direction` |
| 角色定妆 | `ownerType=role` |
| 片段分镜缩略图 | `ownerType=segment`，与 DB `portrait_versions` 一致 |
| 场次 / 场景资产概念图 | `ownerType=scene` / `scene_asset`，且 §2 前置修复后 **`scene_versions` 可读** |
| 错误路径 | 稳定错误前缀，`logs` 可检索 `IMAGE_METADATA` |

## 13. 与项目规范的_alignment

- **命名**：IPC / TS 一律 camelCase；禁止 `projectId` 等废止字段。
- **类型 SSOT**：`ui/src/api/types.ts`。
- **源码注释**：新建 Rust / TS 文件头部中文模块注释；公开函数上方简要中文说明。
- **不在业务代码做离线迁移**：本特性只读现有 JSON；若历史数据缺字段，展示为空即可。
