## 1. 分层模型（L0–L4）

```text
L0  证据层     docs/dev/官方API/*.md + 审计矩阵行（可检索 URL / 摘录）
         ↓
L1  凭证层     VendorTemplate · Credential · base_url / api_key（不含模式能力）
         ↓
L2  场景层     CapabilityType（固定 6 类）× providerKind 白名单 · capabilityBindings
         ↓
L3  目录层     model_capability_catalog + model_official_catalog（按 modelId 分行 · v3）
         ↓
L4  运行时     workbenchIntent → SubmitPlan → apiFamily 适配器 → HTTP
```

| 层 | 回答的问题 | 唯一写入点 | 禁止 |
|----|------------|------------|------|
| **L0** | 官方怎么说 | `docs/dev/官方API/`、DATA 审计矩阵 | 无文档即 `declared_only` 不得标 `implemented` |
| **L1** | 谁付钱 | `settingsV3Catalog` 厂商模板、账号中心 | 在凭证里写 maxImages / 画幅 |
| **L2** | 用户在哪类任务里选这家 | `CAPABILITY_WHITELIST`、bindings 行 | 每个官方 H2 新增第 7 类能力卡片 |
| **L3** | 该 modelId 能做什么、上限多少 | `model_catalog.rs` 种子 + 离线 reseed | 业务 `if (providerKind===…)` 写能力 |
| **L4** | 本次请求怎么发 | `open_platform/{apiFamily}.rs` + dispatch | 工作台 Tab 名直写 URL |

## 3. L2 · 能力映射（设置）规范

### 3.1 固定六类（不可增）

`text` | `image` | `imageToImage` | `video` | `keyframe` | `speech`

### 3.2 何时为同一 `providerKind` 增加 `keyframe` 能力

**同时满足**以下 ≥2 条 → 白名单允许 `keyframe`：

1. 首尾帧使用与 T2V **不同的 model 行**（官方 modelId 不同）。  
2. 需要**独立**默认绑定 / last 偏好 / ModelPicker 池。  
3. 工作台使用**独立大 Tab** 与 `first_last_frame` intent。

否则：首尾帧仅为 `video` 下 `inputModes` 之一（小 Tab/chip），**不**建 `keyframe` 绑定。

### 3.3 禁止

- 为「多图参考」「多模态」「延长视频」各建能力分类。  
- 在 `capabilityBindings` 内存 `maxReferenceImages`（必须从 L3 查）。  
- `KEYFRAME_KIND_*` 与 `VIDEO_KIND_*` 双常量指同一字符串（删除 `KEYFRAME_KIND_DASHSCOPE_WAN`，统一 `video_dashscope_wan`）。

### 3.4 L2 数据一次性净化（死规定 · 不兼容旧绑定）

**目标**：磁盘上 `app_user_settings` / preset 中能力映射与 **SPEC v1 + catalog v3** 完全一致；**多余、重复、废弃 pk 的绑定整行删除**，不做运行时合并兜底。

| 规则 ID | 规则 |
|---------|------|
| **INV-L2-01** | 每个 `(credentialId, capability, providerKind)` 最多 **一条** binding；重复行 **删除**（保留 `order` 最小或用户明确默认的一条，合并脚本须写死策略） |
| **INV-L2-02** | `providerKind` 不在当前 `CAPABILITY_WHITELIST` → **删除** |
| **INV-L2-03** | `capability` 不在该 pk 白名单允许集合 → **删除**（例：即梦旧 720p pk 整行删除） |
| **INV-L2-04** | binding.models 中 modelId 不在 catalog v3 官方表 → **删除该行**；若 binding 变空则 **删除 binding** |
| **INV-L2-05** | keyframe binding 的 model 行 **不得** 含 T2V-only modelId（万相/Seedance 历史污染） |
| **INV-L2-06** | 同一凭证下 keyframe 与 video 复用同一 `providerKind` 时，**model 行集合按** `official_models_for_capability_binding(capability, pk)` **重写在离线脚本中一次完成** |
| **INV-L2-07** | 禁止在 binding 的 JSON 扩展字段存能力参数（张数、画幅、implemented 列表） |
| **INV-L2-08** | 净化后 **仅** 允许通过 `reset_app_user_settings_to_vendor_templates.py` 或 **`scripts/purge_capability_bindings_v3.py`（新建）** 写入；启动路径 **不得** patch 补行 |

**离线脚本交付**（PLAN Track 0/2）：

- `scripts/purge_capability_bindings_v3.py`：读 v3 catalog + 白名单 → 输出删除/合并报告 → 写回 `app_user_settings`  
- `scripts/merge_jimeng_t2v_provider_kinds.py`：三旧 pk 绑定合并到 `video_volc_jimeng_t2v` 后 **删除** 旧 binding  

**验收**：净化后 `verify_capability_bindings_v3.py` 零违规；设置页无重复「万相 2.7」/ 无三条即梦视频入口。

## 4. L3 · catalog v3 规范

### 4.1 表与主键（不变）

`model_capability_catalog(canonical_provider_kind, model_id, task_type)`  
`model_official_catalog(canonical_provider_kind, model_id)`

### 4.2 `caps_json` 版本

- **`schemaVersion`: 3**（破坏性；删除 v1 channel 宽行 `model_id='*'` 作为能力源；仅保留展示用 brief 或迁移后删除）。  
- 每个**已接入** `providerKind` 至少一行 **`model_id` 精确行**；禁止依赖 `*` 行承载 `videoExtensions`。

### 4.3 必填块（视频 model 行）

```json
{
  "schemaVersion": 3,
  "maxPromptChars": 0,
  "videoCapabilities": {
    "supportsTextToVideo": false,
    "supportsImageToVideo": false,
    "supportsMultiImageToVideo": false,
    "supportsReferenceToVideo": false,
    "supportsFirstLastFrame": false,
    "maxReferenceImages": 0,
    "maxReferenceVideos": 0,
    "maxImagesByMode": {}
  },
  "videoExtensions": {
    "inputModes": [],
    "implementedModeIds": [],
    "featureModules": [],
    "constraintRules": [],
    "generic": {}
  }
}
```

### 4.4 `inputModes[]` 条目

| 字段 | 要求 |
|------|------|
| `id` | `vendorModeId` |
| `labelZh` | 设置副行 / 灰显 chip 文案 |
| `implementationStatus` | `implemented` \| `declared_only` \| `deprecated` |
| `workbenchIntent` | **必填**（v3 新增，替代隐式映射） |
| `routing.apiFamily` | L4 路由键 |
| `input` | `maxImages` / `maxVideos` / `maxAudios` / `required` |
| `generation` | 画幅/时长/分辨率可选集；`null` 表示跟 generic |
| `fieldPolicy` | 按 mode 隐藏画幅/时长等 |

### 4.5 一致性死规定（INV-CAT）

| ID | 规则 |
|----|------|
| **INV-CAT-01** | `implementedModeIds` 中每一项 `implementationStatus` 必须为 `implemented` |
| **INV-CAT-02** | `implemented` 的 mode 必有 `workbenchIntent`，且存在于 §2.2 枚举 |
| **INV-CAT-03** | `videoCapabilities.supportsX` 为 true 当且仅当存在某 `implemented` mode 映射到对应 intent 语义 |
| **INV-CAT-04** | `maxImagesByMode[intent]` 与 `constraintRules` 不得矛盾；矛盾则种子非法 |
| **INV-CAT-05** | `declared_only` 不得出现在 `implementedModeIds` |
| **INV-CAT-06** | 无 L0 文档摘录的 mode 只能 `declared_only` |

### 4.6 `constraintRules`（互斥/上限）

- 类型：`max` | `mutex` | `require` | `forbid`（schema 见 `scripts/model_caps_schema_v3.json`）。  
- 前端 `computeVideoCapabilityConflict` / 图像等价物 **只读** rules，禁止重复实现 Seedance 单图规则等于两处。
