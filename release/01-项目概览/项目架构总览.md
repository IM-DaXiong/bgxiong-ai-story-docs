## 一、项目简介

**比格熊数字导演工作站（BGXiong Digital Director Workstation）** 是一款面向影视创作者的 **AI 驱动的桌面端创作平台**。它将剧本写作、角色设计、分镜绘制、视频剪辑等环节整合到统一的工作流中，通过接入多种 AI 大模型，让个人创作者也能完成原本需要一整个团队才能做到的影视前期工作。

**核心定位**：用 AI 把创意变成可视化的故事 — 从一段文字描述，到有角色、有画面、有声音的完整影像脚本。

### 核心特色：云端 + 本地双引擎架构

比格熊是目前唯一同时把 **六大云端厂商**（火山引擎、通义千问、即梦、可灵、DeepSeek、OpenAI 兼容网关）和 **三大本地开源引擎**（ComfyUI、IndexTTS-2、VoxCPM2）无缝整合到一个统一调度层的 AI 创作平台。用户只需决定"这个任务用哪个引擎"，无需纠结"这个能不能用"。

### 谁在用？

- 短视频创作者、自媒体博主
- 独立导演、编剧
- 影视前期策划人员
- 需要快速出概念图/分镜的创意工作者

## 二、整体架构

```
┌──────────────────────────────────────────────────────────────────┐
│                         👤 用户界面                               │
│               React 前端 · 画布操作 · 工作台 · 设置                 │
├──────────────────────────────────────────────────────────────────┤
│                         🔗 通信桥梁                               │
│                  Tauri IPC · HTTP Bridge · SSE                    │
├──────────────────────────────────────────────────────────────────┤
│                         ⚙️  业务引擎                              │
│            Rust 后端 · AI 任务调度 · 媒体处理 · SQLite              │
├──────────────────────────┬───────────────────────────────────────┤
│       ☁️ 云端 AI 厂商层    │        🏠 本地 AI 引擎层               │
│   OpenAI · Jimeng · Kling │  ComfyUI · IndexTTS-2 · VoxCPM2      │
│   Qwen · Minimax · ...   │  Whisper · GGUF · Piper               │
│   火山引擎 · 通义千问      │  本地模型（文本/图片/视频/语音）         │
├──────────────────────────┴───────────────────────────────────────┤
│                         🔌 外部集成                               │
│           DaVinci Resolve 插件 · 云端服务器                        │
└──────────────────────────────────────────────────────────────────┘
```

**一句话概括**：前端像纸笔一样轻量，所有重活（AI 调用、数据库、音视频处理）全部交给 Rust 后端。云端有云端的强，本地有本地的香 — 同一套界面、同一套操作、两套动力系统随你切换。

## 三、核心功能模块

### 3.1 故事工厂（Story Studio）

| 模块 | 说明 |
|------|------|
| **故事管理** | 创建/编辑故事，支持 Word/PDF/文本拖入自动提取故事描述 |
| **剧集规划** | 将故事拆分为"剧集 → 场次 → 片段"三级结构，AI 辅助生成大纲 |
| **画面风格** | 12 档风格预设（电影级/日系/赛博朋克等），可自定义，一键应用到全项目 |
| **故事圣经** | 世界观、人物关系、场景设定等结构化文档，支持版本历史与自动保存 |

### 3.2 角色设计（Character Studio）

| 模块 | 说明 |
|------|------|
| **角色管理** | 创建角色档案，录入年龄、外貌、性格、背景故事 |
| **演员定妆** | 基于角色描述生成定妆照，支持正/侧/背面多视角，自动匹配面部特征 |
| **参考图策略** | 灵活管理 AI 生图所用的垫图（参考图），支持角色绑定与按需切换 |
| **演员提取** | 从故事文本中自动识别角色信息，AI 辅助补全 |

### 3.3 分镜系统（Storyboard）

| 模块 | 说明 |
|------|------|
| **分镜画布** | 无限画布上拖拽排列分镜卡片，像使用思维导图一样规划镜头 |
| **AI 批量生图** | 一键为所有分镜生成静帧画面，自动保持角色和风格一致性 |
| **摄影语言** | 景别、机位、构图、焦段等电影专业参数的 AI 自动推理 |
| **分镜历史** | 每张分镜的生成历史完整保留，可回退、对比、设为首选 |

### 3.4 片段/视频工作台（Segment Studio）

| 模块 | 说明 |
|------|------|
| **片段编辑** | 在画布上组织片段节点，管理播放顺序与转场 |
| **视频生成** | AI 文生视频/图生视频，支持云端+本地 ComfyUI 双引擎 |
| **音频管线** | 语音识别（云端+本地 Whisper）、自动字幕、音频对齐 |
| **剪辑框架** | 素材管理、剪辑序列、导出标记 |

### 3.5 TTS 语音合成（Voice Studio）

| 模块 | 说明 |
|------|------|
| **云端 TTS** | 火山引擎、通义千问等云端高品质语音合成 |
| **本地 TTS** | IndexTTS-2（情感控制+音色克隆）、VoxCPM2（零样本克隆+声音设计）、Piper |
| **语音设计** | 文字描述声音特征直接合成，无需真实参考音频 |
| **Sidecar 架构** | Python TTS 引擎以独立子进程运行，自动探测 Python 环境与 GPU 资源 |

### 3.6 视觉资产库

独立于故事的 **通用素材管理** 模块 — 角色、场景、道具的图片资产统一存储，支持概念图生成、垫图复用，不绑定特定故事 ID。

| 模块 | 说明 |

| **信封通信** | 客户端与达芬奇插件之间的通用命令通道，支持同步/异步/SSE 三模式 |

### 3.8 本地模型管理（Local Models Hub）

| 模块 | 说明 |
|------|------|
| **运行时 CDN 安装** | FFmpeg / Whisper / Llama / IndexTTS / VoxCPM 一键自动下载部署 |

### 4.3 本地服务关键架构决策

#### CDN 延迟下载模型

所有外部运行时（FFmpeg / Whisper / Llama / IndexTTS / VoxCPM）**不随 NSIS 安装包分发**，而是在用户首次使用时从 CDN 按需下载：

```
用户点击"启用" → 检查本地是否已安装
    ├── 已安装且版本匹配 → 直接启动
    └── 未安装/版本过期
        → Manifest 解析（按平台+变体匹配版本号）
        → 通用下载器（Range 续传 + SHA256 校验）
        → 解压到 {app_data}/runtimes/{type}/
        → 写入 active.json（版本追踪）
        → 启动引擎
```

好处：安装包体积小、运行时独立更新、多版本共存、断点续传不浪费流量。

#### TTS Sidecar 架构

IndexTTS-2 和 VoxCPM2 是 Python 生态的模型，通过 **Sidecar 子进程** 模式集成：

```
Rust 主进程
    │ spawn Python subprocess (hidden window)
    │
    ├── Python Runtime Probe → 自动探测系统 Python / venv
    ├── GPU VRAM Probe → 检查显存是否满足最低要求
    ├── Port Pool Scan → 分配空闲端口
    │
    ▼
Python Sidecar (独立进程)
    │ HTTP REST API (localhost:{port})
    │
    ├── POST /v1/indextts/synthesize  (情感控制 + 音色克隆)
    ├── POST /v1/audio/speech         (VoxCPM2 零样本克隆)
    └── GET  /health                  (健康检查)
```

好处：Python 依赖与 Rust 主进程隔离、引擎崩溃不影响主程序、可独立升级。

#### ComfyUI 工作流引擎

ComfyUI 不仅是一个 HTTP 客户端，而是完整的 **工作流生命周期管理**：

```
Scanner → Normalizer → Resolver → Injector → Compiler → Hydrate
(发现)    (规范化)     (解析)     (注入)     (编译)     (水合)
```

- **Scanner**：从磁盘发现用户自定义工作流模板
- **Normalizer**：统一不同版本的工作流格式
- **Resolver**：解析节点依赖和类型约束
- **Injector**：注入角色/风格/提示词等业务参数
- **Compiler**：编译为 ComfyUI API 可执行的 JSON
- **Hydrate**：用实际参数值水合模板占位符

## 五、技术架构特点与优势

### 5.1 云端+本地双引擎统一调度

用户操作完全一致 — 同一套界面、同一种交互，切换引擎只是后台偏好设置的事。前端不需要知道底层跑的是云端还是本地。

### 5.2 高内聚、低耦合的分层设计

```
前端（薄编排层）        Rust 后端（重计算层）
─────────────────      ─────────────────────
只负责：                只负责：
• 界面渲染             • 数据库读写
• 参数组装             • AI 任务调度
• 用户交互             • 音视频处理
                        • 复杂业务逻辑
                        • 本地引擎生命周期
```

### 5.3 单一数据源（SSOT）

项目中每一条数据规则只有一个权威来源，从数据库字段到 API 到前端类型定义，命名和含义完全一致。

### 5.4 自动化质量门禁

项目内置 **220+ 合规检查脚本**（`check-*-ssot.ps1`），每一次代码改动都会被多项自动化规则检查。

### 5.5 离线优先 + 本地数据主权

- 核心数据库使用 **SQLite** 存储在用户本地，断网也能正常工作
- 本地模型推理数据完全不出本机
- 云端服务器仅用于：账号注册、权限验证、订阅管理、资源下载

### 5.6 破坏性修复许可

当发现设计缺陷时，允许 **彻底重写** 而非打补丁凑合。

### 5.7 离线迁移策略

数据库结构变更全部通过 **离线迁移脚本** 完成，不在程序运行时偷偷改表结构。

### 5.8 无限画布引擎

自研画布系统：无限缩放平移、节点连线、LOD 瓦片缩略图、完整撤销/重做。零外部依赖。

## 八、总结

比格熊数字导演工作站的架构核心思路是 **"前端做减法，后端做加法，本地做乘法"**：

- **前端** 保持轻量，只做界面展示和用户交互，不越界处理业务逻辑
- **后端** 用 Rust 承载所有重计算、数据库、AI 调度、媒体处理
- **本地引擎** 从"辅助"升级为"对等主力"——**本地服务代码量半年翻倍（+121%）**
- **中间** 通过严格的接口规范和数据契约连接前后端
- **外围** 用 220+ 自动化脚本守住代码质量底线
- **双引擎** 不是两套割裂体验拼在一起，而是统一的创作界面下有两套动力系统随你切换

这种架构让项目在代码量超过 **73 万行**（含文档超 **119 万行**）的规模下，仍然保持清晰的模块边界和可控的维护成本。
