## 一、概述

比格熊数字导演工作站采用 **Tauri 2（Rust 后端） + React 19 + TypeScript（前端）** 的桌面应用架构。整体遵循**六边形架构**（Hexagonal / Ports & Adapters），后端分为 `domain → application → infrastructure` 三层，前端采用 `domain → components` 分层。

### 全仓代码规模

| 类别 | 文件数 | 代码行数 | 占比 |
|------|--------|----------|------|
| Rust 后端（src-tauri/src） | 1,542 | ~283,800 | 39.8% |
| Rust 核心库（src/） | 24 | 1,761 | 0.2% |
| TypeScript 前端（ui/src） | 3,509 | ~395,200 | 55.4% |
| CSS（ui/src） | 9 | 2,056 | 0.3% |
| 脚本（scripts/） | 314 | 30,935 | 4.3% |
| 文档（docs/） | 1,516 | 359,095 | — |
| **合计（含代码）** | **5,398** | **~713,800** | — |
| **合计（含文档）** | **6,914** | **~1,072,900** | — |

### 架构层级总览

```
┌──────────────────────────────────────────────────────┐
│ 前端（ui/src/）                                       │
│  React 组件层（components/）· 业务逻辑层（domain/）     │

├──────────────────────────────────────────────────────┤

│  │（IPC入口）│→│（业务服务） │→│（SQLite持久化）    │ │
│  └──────────┘  └────────────┘  └──────────────────┘ │

│  │ 业务模块（image_generation, media_preprocess, │   │
```

## 三、后端 — src-tauri/src/

**架构模式**：六边形架构（Ports & Adapters） + 垂直业务模块  
**技术栈**：Rust · rusqlite · Tokio · reqwest · axum · Candle/GGUF（本地AI）  
**代码量**：~283,800 行，1,542 个 `.rs` 文件，80+ 业务模块

### 3.1 六边形架构核心层（基础设施）

| 目录 | 行数 | 文件数 | 作用 |
|------|------|--------|------|
| **infrastructure/** | 43,085 | 175 | 持久化层（SQLite 实现）。`persistence/sqlite/` 包含所有 Repository 的 rusqlite 实现。`delete_orchestration/` 负责级联删除编排。全仓唯一允许直接使用 rusqlite 的模块 |
| **domain/** | 1,139 | 24 | 领域层。`entities/`（领域实体定义），`ports/`（Repository trait 接口）。**禁止** import rusqlite/Tauri/reqwest |
| **application/** | 7,939 | 78 | 应用服务层。`services/`（业务用例编排），`ports/`（应用层接口），`dto/`（数据传输对象） |
| **db/** | 9,389 | 52 | 数据库核心。`pool.rs`（连接池管理），`schema.rs`（表结构定义），`model_catalog_repo.rs`（模型目录仓库），`migrations/`（数据库迁移实现），`backup.rs`（备份逻辑） |

**架构约束**：
```
commands/IPC/pipeline（薄入口）
    ↓ 调用
application::services（用例编排，返回 ApplicationError）
    ↓ 依赖 trait
domain::ports（Repository 接口，纯抽象）
    ↓ 实现
infrastructure::persistence::sqlite（唯一 rusqlite 实现）
    ↓ 持有
db::DbState（连接池，仅 AppContainer 内部持有）
```

## 五、前端 — ui/src/

**架构模式**：领域驱动前端分层（Domain Layer + Component Layer）

### 5.1 分层概览

```
components/（UI 组件层，薄展示）
    ↓ 使用
domain/（业务逻辑层，状态管理、API调用编排）
    ↓ 调用
api/（Tauri IPC invoke 封装）
    ↕
graph-core/（图数据结构核心）
    ↓ 被使用
infinite-canvas/（通用无限画布引擎）
    ↑ 被嵌入
features/（特性模块：角色Tab、场景Tab）
```

## 十一、全局架构模式与统计

### 11.1 核心架构模式

| 模式 | 应用范围 | 说明 |
|------|----------|------|
| **六边形架构（Ports & Adapters）** | 后端全量 | `domain::ports`（接口） → `application::services`（用例） → `infrastructure::persistence::sqlite`（实现） |
| **DDD 领域驱动** | 后端 `domain/` | 实体（Entity）、端口（Port/Repository trait）、值对象 |
| **垂直业务模块** | 后端 `src-tauri/src/` | 每个功能域为独立模块（image_generation、media_preprocess、chapter_scenes_plan 等），高内聚低耦合 |
| **领域前端分层** | 前端 `ui/src/domain/` | 业务逻辑与 UI 分离，domain 层不直接 import 组件 |
| **多窗口架构** | 前端 | 主窗口 + 5 个独立 WebView 弹窗（assistant/clips/refine/segment/storyboard） |
| **通用画布引擎** | 前端 `infinite-canvas/` | 零外部依赖，K7 内核拆分，多特性复用 |
| **SSOT 单一数据源** | 全仓 | 每个数据规则只有一处权威来源，从 SQLite 字段到 IPC 到 TypeScript 类型定义 |
| **INV 不变式门禁** | 全仓 `scripts/` | 120+ PowerShell 脚本强制执行架构契约，CI 集成 |
| **离线迁移** | 数据库 | 表结构变更全部通过离线 `scripts/` 脚本，禁止运行时 ALTER |
