# 无限画布瀑布流性能优化设计与排列算法

## 1. 概述

本文档详细记录项目中**无限画布瀑布流布局**的排列算法、交互规范与性能优化方案。该画布系统被多个模块复用（演员形象区 `CharacterTab`、场次画布 `SceneTab`、分镜历史 `StoryboardShotCanvas`、片段模块 `SegmentCanvas` 等），是项目 UI 交互的核心基础设施之一。

---

## 2. 画布交互规范

### 2.1 基本交互

| 操作 | 行为 | 说明 |
|------|------|------|
| 中键拖拽 | 平移画布 | 空白区域与卡片区域均有效 |
| 滚轮缩放 | 锚点缩放（zoom to cursor） | 以鼠标位置为缩放中心，45%~500% |
| 左键框选 | 多选节点 | 空白区左键拖拽形成矩形选框 |
| 左键拖拽卡片 | 移动节点 | 按住即进入抓取态，松手固定 |
| 右键菜单 | 上下文操作 | 含「设为默认图」「删除」等 |
| 重置入口 | 恢复初始状态 | 重置 `pan`/`scale` 与 masonry 初始排布 |
| `Ctrl/Cmd + 左键` | 强制框选 | 图片密集时避免手势被卡片拖拽抢占 |

### 2.2 光标规范

- **常态**：系统箭头光标（`cursor: default`）
- **左键按下至松手**（含未超过位移阈值、未出现幽灵层之前）：该行与 `document.body` 均为 `cursor: grabbing`
- **松手后**：恢复系统箭头
- **禁止**：整行常驻 `grab` 或 `pointer`，以免与「可点链接」混淆

实现上须复用 `usePointerReorderList` hook（`ui/src/hooks/usePointerReorderList.ts`）。

### 2.3 选中置顶（强制）

画布上处于选中态（单选高亮、框选多选集合内）的图片/卡片，其堆叠顺序（`z-index` 或等价层叠上下文）**必须高于**所有未选中项。正在拖拽的项须在选中基线之上再抬高（或至少不低于选中基线），保证拖移过程中仍不被未选图遮挡。

## 3. 瀑布流排列算法（Masonry Layout）

### 3.1 算法核心

使用 **Pinterest 风格固定列宽瀑布流**，高度自适应，物品放入最短列。

```typescript
// ui/src/domain/castPortraitMasonryLayout.ts

export const CAST_PORTRAIT_MASONRY_GAP_PX = 8;
export const CAST_PORTRAIT_MASONRY_MIN_COL_PX = 140;

export function layoutCastPortraitMasonry(
  items: CastPortraitMasonryItem[],
  containerWidth: number,
  opts?: { gap?: number; minColWidth?: number },
): CastPortraitMasonryLayout {
  const gap = opts?.gap ?? CAST_PORTRAIT_MASONRY_GAP_PX;
  const minColWidth = opts?.minColWidth ?? CAST_PORTRAIT_MASONRY_MIN_COL_PX;

  // 容器宽度未就绪时，使用最小列宽作为默认值
  const W = containerWidth > 0 ? containerWidth : minColWidth;

  if (items.length === 0) {
    return { positions: new Map(), totalHeight: 0, columnCount: 1, columnWidth: minColWidth };
  }

  // 计算列数
  const colCount = Math.min(items.length, Math.max(1, Math.floor((W + gap) / (minColWidth + gap))));
  const colW = (W - gap * (colCount - 1)) / colCount;

  // 每列当前高度
  const colHeights: number[] = new Array(colCount).fill(0);
  const positions = new Map<string, CastPortraitMasonryPosition>();

  for (const item of items) {
    const ar = clampAspectRatio(item.aspectRatio);
    const h = colW / ar;

    // 找到最短列
    let shortestCol = 0;
    let minHeight = colHeights[0];
    for (let c = 1; c < colCount; c++) {
      if (colHeights[c] < minHeight) {
        minHeight = colHeights[c];
        shortestCol = c;
      }
    }

    const x = shortestCol * (colW + gap);
    const y = colHeights[shortestCol];

    positions.set(item.key, { x, y, w: colW, h });
    colHeights[shortestCol] = y + h + gap;
  }

  const maxHeight = Math.max(...colHeights);
  const totalHeight = maxHeight > gap ? maxHeight - gap : maxHeight;

  return {
    positions,
    totalHeight: Math.max(0, totalHeight),
    columnCount: colCount,
    columnWidth: colW,
  };
}

function clampAspectRatio(r: number): number {
  if (!Number.isFinite(r) || r <= 0) return 3 / 4;
  return Math.min(2.5, Math.max(0.5, r));
}
```

### 3.2 计算规则（强制）

1. **必须按画布内容区宽度**计算 masonry（`clientWidth`），不得按外边框宽度计算
2. **列数公式**：`colCount = min(items.length, floor((W + gap) / (minColWidth + gap)))`
3. **列宽公式**：`colW = (W - gap * (colCount - 1)) / colCount`
4. **物品高度**：`h = colW / aspectRatio`
5. **宽高比钳制**：`[0.5, 2.5]`，非有限值兜底为 `3/4`
6. **容器未就绪**：回退到 `minColWidth` 作为默认宽度，确保至少单列布局

### 3.3 CSS 实现要点

- 使用 `position: absolute` 定位每个 tile（**禁止** JSX 内联覆盖为 `relative`）
- 容器不设固定高度，使用计算出的 `totalHeight`
- 图片使用 `object-fit: cover` 填满 tile
- 瀑布流 tile 样式在 `ui/src/index.css` 中统一管理

## 4. 缩放算法（Zoom to Cursor）

### 4.1 锚点保持公式（强制）

使用一次性原子更新 `pan/scale`（同一事件内计算，避免连续滚轮漂移）：

```
world = (anchor - pan_old) / scale_old
scale_new = clamp(scale_old * zoomFactor, minScale, maxScale)
pan_new = anchor - world * scale_new
```

**然后同一帧提交 `pan_new + scale_new`**，不得分两次异步推导。

### 4.2 参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `minScale` | 0.45 | 最小缩放 45% |
| `maxScale` | 5.00 | 最大缩放 500% |
| `zoomFactor` | 1.08 | 滚轮每档比例 |

### 4.3 锚点坐标计算

缩放中心坐标必须按**画布内容区**计算（扣除边框/装饰）：

```
anchor_x = clientX - host.getBoundingClientRect().left - host.clientLeft
anchor_y = clientY - host.getBoundingClientRect().top - host.clientTop
```

### 4.4 验收标准

鼠标停在图片特征点（如眼睛）连续滚轮放大/缩小，该特征点始终贴在鼠标位置，不漂移。

## 5. 框选与多选算法

### 5.1 框选判定

- 框选框使用**屏幕坐标**（`clientX/clientY`）
- 图片命中框必须换算到屏幕坐标：
  ```
  screenX = host.getBoundingClientRect().left + host.clientLeft + pan + worldX * scale
  screenY = host.getBoundingClientRect().top + host.clientTop + pan + worldY * scale
  ```
- **禁止**混用画布局部坐标与屏幕坐标
- **相交即选中**（框选矩形与图片可视外接矩形相交）
- 单击空白处应清空框选态

### 5.2 多选拖动

- 拖拽命中已选中集合且集合数 > 1 时：
  1. 记录全部初始位置
  2. 同步增量更新
  3. 增量换算统一使用实时 `scaleRef.current`

### 5.3 多选保持

- 多选态下点击已选项（未发生拖动）**不得**塌缩为单选
- 仅非多选态点击时才切为单选

## 6. 画布状态持久化与恢复

### 6.1 存储结构

```typescript
interface CanvasState {
  version: number;                              // 版本号，用于迁移
  scene_id: string;                            // 场次 ID
  pan: { x: number; y: number };
  scale: number;
  tilePositions: Record<string, { x: number; y: number }>; // 节点位置
  minimized: boolean;                          // 侧边栏状态
  last_updated: string;                        // ISO 时间戳
}
```

### 6.2 存储方案

| 方案 | 限制 | 适用场景 |
|------|------|----------|
| `localStorage` | 5~10 MB | 不推荐（节点 > 50 时超限） |
| `tauri-plugin-store` | 无明确限制（磁盘） | 推荐（自动 JSON 持久化） |
| SQLite | 无明确限制 | 推荐（复杂查询、事务支持） |

存储键按场次维度独立：`canvas_state_{scene_id}.json`

### 6.3 恢复规则

1. **全量坐标恢复**：不仅恢复拖动过的图片，当前画布中所有可见图片都应有确定位置
2. **优先用缓存位置**；无缓存项回落到默认 masonry 落位后**立即纳入快照**
3. **缓存回放兜底**：读取 `tiles` 时先清洗无效坐标；当无有效坐标时，必须强制 `tilesCustomized = false`，默认回落到 masonry 初始布局（**不允许**出现"默认竖一列"）

### 6.4 位置同步策略

- 缓存增加分镜节点位置的 **version 标识**（基于故事板节点 `updated_at` 哈希）
- 基于稳定标识符重连：使用分镜节点的 `shot_id` 而非 `name`
- 画布位置缓存保存 `{ segment_shot_id } → { x, y }` 映射
- 若故事板分镜布局已更新，弹出提示用户是否同步
- **视频片段节点的位置始终独立存储**，不受故事板同步影响

## 7. 分镜历史画布拖拽（2026-04-07 经验固化）

### 7.1 拖拽状态管理

1. **左键按下图片即进入抓取态**（不等待拖拽阈值）；松手立刻释放并固定位置
2. **必须禁用原生图片拖拽**（`draggable={false}` + `onDragStart.preventDefault`），避免浏览器拖图态抢占 `mouseup`
3. 拖拽高频更新使用 `requestAnimationFrame` 聚合；`mousemove` 仅写入最新指针增量，`mouseup` 必须 `flush` 最后一帧后再清理状态，避免终点跳变

### 7.2 世界层统一 Transform

- 平移/缩放采用"世界层统一 transform"（容器 `translate + scale`）
- 单 tile 仅保留世界坐标
- **避免**每帧给全部 tile 重算 `pan/scale` 后位置

### 7.3 Minimap 优化

- 拖拽进行中可冻结 minimap 重算并复用缓存
- 结束后再恢复实时计算，保证主视图跟手

### 7.4 收尾监听

至少覆盖 `mouseup + mouseleave + blur`，防止窗口焦点切换导致拖拽状态悬挂。

## 8. 渲染性能优化

### 8.1 Zustand 替代 useState

多个视频节点同时生成时，`segment_video_progress` 事件可能非常密集，导致 React 频繁重渲染卡顿。

**解决方案**：使用 Zustand 原子状态管理，按节点独立订阅。

```typescript
// ui/src/stores/segmentVideoStore.ts

import { create } from 'zustand';

interface SegmentVideoStore {
  nodes: Record<string, VideoNodeUiState>;
  updateNodes: (updates: Record<string, Partial<VideoNodeUiState>>) => void;
  updateNode: (segmentId: string, update: Partial<VideoNodeUiState>) => void;
  clearTask: (segmentId: string) => void;
}

export const useSegmentVideoStore = create<SegmentVideoStore>((set) => ({
  nodes: {},

  updateNodes: (updates) =>
    set((state) => {
      const newNodes = { ...state.nodes };
      for (const [id, update] of Object.entries(updates)) {
        newNodes[id] = { ...newNodes[id], ...update };
      }
      return { nodes: newNodes };
    }),

  updateNode: (segmentId, update) =>
    set((state) => ({
      nodes: {
        ...state.nodes,
        [segmentId]: { ...state.nodes[segmentId], ...update },
      },
    })),

  clearTask: (segmentId) =>
    set((state) => ({
      nodes: {
        ...state.nodes,
        [segmentId]: {
          ...state.nodes[segmentId],
          isGenerating: false,
          taskStage: null,
          progressPercent: null,
        },
      },
    })),
}));
```

### 8.2 节流监听器

```typescript
// ui/src/hooks/useSegmentVideoProgressThrottled.ts

const THROTTLE_MS = 500;

export function useSegmentVideoProgressThrottled() {
  const updateNodes = useSegmentVideoStore((s) => s.updateNodes);
  const pendingUpdates = useRef<Map<string, SegmentVideoProgressPayload>>(new Map());
  const throttledFn = useRef<NodeJS.Timeout | null>(null);

  useEffect(() => {
    let unlisten: (() => void) | null = null;

    const setup = async () => {
      unlisten = await listen<SegmentVideoProgressPayload>(
        'segment_video_progress',
        (event) => {
          const payload = event.payload;
          pendingUpdates.current.set(payload.segment_id, payload);

          if (!throttledFn.current) {
            throttledFn.current = setTimeout(() => {
              const updates = pendingUpdates.current;
              pendingUpdates.current = new Map();

              const storeUpdates: Record<string, Partial<VideoNodeUiState>> = {};
              for (const [id, p] of updates) {
                storeUpdates[id] = {
                  taskStage: p.stage,
                  progressPercent: p.progress_percent ?? null,
                  queuePosition: p.queue_position ?? null,
                  errorMessage: p.error_message ?? null,
                  isGenerating: p.stage === 'submitted' || p.stage === 'processing',
                };
              }

              if (Object.keys(storeUpdates).length > 0) {
                updateNodes(storeUpdates);
              }

              throttledFn.current = null;
            }, THROTTLE_MS);
          }
        }
      );
    };

    setup();
    return () => {
      if (unlisten) unlisten();
      if (throttledFn.current) clearTimeout(throttledFn.current);
    };
  }, [updateNodes]);
}
```

## 9. 节点超量优化：虚拟渲染（Virtualized / Windowed Rendering）

### 9.1 问题背景

当画布节点数量达到 200+、500+ 时，即使有视口裁剪和 IntersectionObserver，**首次渲染仍需创建全部 React 组件**（`allNodes.map(...)` 在虚拟 DOM 阶段就生成全部节点），导致：
- 首次加载卡顿（React  reconciliation + DOM 创建耗时）
- 内存中保留全部组件实例
- 状态变化时仍遍历全部组件

### 9.2 核心思路

**只创建视口内 + 缓冲区内的 React 组件**，远端节点不进入虚拟 DOM，仅在平移/缩放到其区域时动态挂载。

```
┌─────────────────────────────────────────────────┐
│                  画布全量范围                      │
│                                                  │
│   ┌────────────────────────────────────┐         │
│   │        视口 (Viewport)              │         │
│   │   ┌──────────────────────┐         │         │
│   │   │  当前可见节点（渲染）   │         │         │
│   │   └──────────────────────┘         │         │
│   │                                    │         │
│   │   [缓冲区: 视口外扩展 200px]        │         │
│   │   预渲染相邻节点，确保拖拽流畅        │         │
│   └────────────────────────────────────┘         │
│                                                  │
│   [远端节点: 不创建 DOM，只保留世界坐标数据]       │
│   平移/缩放进入缓冲区时动态挂载                     │
└─────────────────────────────────────────────────┘
```

### 9.3 useWindowedCanvasNodes Hook

```typescript
// ui/src/hooks/useWindowedCanvasNodes.ts

import { useMemo, useRef, useCallback } from 'react';

interface CanvasNode {
  id: string;
  x: number;
  y: number;
  width: number;
  height: number;
}

interface WindowedResult {
  /** 当前应渲染的节点集合（视口 + 缓冲区） */
  renderedNodes: CanvasNode[];
  /** 渲染节点 ID 集合（快速查找） */
  renderedIds: Set<string>;
  /** 总节点数 */
  totalCount: number;
}

/**
 * 虚拟渲染：仅返回视口 + 缓冲区内的节点
 * @param allNodes - 全部节点数据（纯数据，不创建组件）
 * @param viewport - 当前视口参数（由画布 pan/scale 计算）
 * @param buffer - 缓冲区扩展像素（默认 200px）
 */
export function useWindowedCanvasNodes(
  allNodes: CanvasNode[],
  viewport: {
    panX: number;
    panY: number;
    scale: number;
    width: number;  // 画布容器可视宽度
    height: number; // 画布容器可视高度
  },
  buffer: number = 200,
): WindowedResult {
  const { panX, panY, scale, width, height } = viewport;

  // 计算视口在世界坐标系中的范围
  const worldLeft = -panX / scale;
  const worldTop = -panY / scale;
  const worldRight = (width - panX) / scale;
  const worldBottom = (height - panY) / scale;

  // 缓冲区扩展（世界坐标）
  const bufX = buffer / scale;
  const bufY = buffer / scale;

  const cullLeft = worldLeft - bufX;
  const cullTop = worldTop - bufY;
  const cullRight = worldRight + bufX;
  const cullBottom = worldBottom + bufY;

  const renderedNodes: CanvasNode[] = [];
  const renderedIds = new Set<string>();

  for (const node of allNodes) {
    const nodeRight = node.x + node.width;
    const nodeBottom = node.y + node.height;

    // AABB 相交检测：节点矩形与裁剪矩形是否相交
    if (
      nodeRight >= cullLeft &&
      node.x <= cullRight &&
      nodeBottom >= cullTop &&
      node.y <= cullBottom
    ) {
      renderedNodes.push(node);
      renderedIds.add(node.id);
    }
  }

  return { renderedNodes, renderedIds, totalCount: allNodes.length };
}
```

### 9.4 画布组件集成

```tsx
// ui/src/components/SegmentCanvas.tsx

import { useState, useRef, useCallback, useEffect } from 'react';
import { useWindowedCanvasNodes } from '../hooks/useWindowedCanvasNodes';

export function SegmentCanvas({
  allSegments,
}: {
  allSegments: VideoSegmentNode[];
}) {
  const containerRef = useRef<HTMLDivElement>(null);
  const [viewport, setViewport] = useState({
    panX: 0, panY: 0, scale: 1,
    width: 0, height: 0,
  });

  // 监听容器尺寸变化
  useEffect(() => {
    const el = containerRef.current;
    if (!el) return;
    const ro = new ResizeObserver((entries) => {
      for (const entry of entries) {
        setViewport((prev) => ({
          ...prev,
          width: entry.contentRect.width,
          height: entry.contentRect.height,
        }));
      }
    });
    ro.observe(el);
    return () => ro.disconnect();
  }, []);

  // 虚拟渲染：仅计算视口内的节点
  const { renderedNodes, renderedIds, totalCount } = useWindowedCanvasNodes(
    allSegments.map(s => ({
      id: s.id,
      x: s.x,
      y: s.y,
      width: s.width ?? 280,
      height: s.height ?? 200,
    })),
    viewport,
    200, // 缓冲区
  );

  // pan/scale 变化时更新视口
  const updateViewport = useCallback((panX: number, panY: number, scale: number) => {
    setViewport((prev) => ({ ...prev, panX, panY, scale }));
  }, []);

  return (
    <div ref={containerRef} className="canvas-container">
      {/* 世界层 transform */}
      <div
        className="world-layer"
        style={{
          transform: `translate(${viewport.panX}px, ${viewport.panY}px) scale(${viewport.scale})`,
        }}
      >
        {/* 仅渲染视口内的节点 */}
        {renderedNodes.map((node) => (
          <VideoSegmentNode
            key={node.id}
            segmentId={node.id}
            position={{ x: node.x, y: node.y }}
          />
        ))}

        {/* SVG 连线层（也仅渲染视口内连线） */}
        <svg className="connections-layer" style={{ position: 'absolute', inset: 0 }}>
          {renderConnectionsBetween(renderedIds, allSegments)}
        </svg>
      </div>
```

### 9.5 初始加载优化：分批渲染

当首次进入一个场次时，如果该场次有大量节点（100+），应**分批挂载**而非一次性全量创建。

```typescript
// ui/src/hooks/useBatchMount.ts

import { useState, useEffect, useRef } from 'react';

/**
 * 分批挂载 Hook
 * @param totalItems - 总数据量
 * @param batchSize - 每批数量（默认 30）
 * @param intervalMs - 每批间隔（默认 16ms，约 1 帧）
 */
export function useBatchMount(
  totalItems: number,
  batchSize: number = 30,
  intervalMs: number = 16,
): { mountCount: number; done: boolean } {
  const [mountCount, setMountCount] = useState(0);
  const rafRef = useRef<number[]>([]);
  const timerRef = useRef<NodeJS.Timeout[]>([]);

  useEffect(() => {
    setMountCount(0);
    // 清理之前的定时器
    rafRef.current.forEach(raf.cancel);
    timerRef.current.forEach(clearTimeout);
    rafRef.current = [];
    timerRef.current = [];

    const batches = Math.ceil(totalItems / batchSize);
    for (let i = 0; i < batches; i++) {
      const timer = setTimeout(() => {
        setMountCount(Math.min((i + 1) * batchSize, totalItems));
      }, i * intervalMs);
      timerRef.current.push(timer);
    }

    return () => {
      timerRef.current.forEach(clearTimeout);
    };
  }, [totalItems, batchSize, intervalMs]);

  return { mountCount, done: mountCount >= totalItems };
}
```

### 9.6 三层优化栈总结

| 层级 | 方案 | 解决的问题 | 生效时机 |
|------|------|------------|----------|
| **L1 虚拟渲染** | `useWindowedCanvasNodes` | 首次渲染 200+ 节点卡顿 | React 虚拟 DOM 阶段 |
| **L2 视口裁剪** | `display: none` 隐藏 | 视口外节点占用 DOM 内存 | DOM 树创建后 |
| **L3 内存回收** | IntersectionObserver | 视频解码器/媒体元素内存 | 节点在 DOM 中但移出视口 |

- **L1** 阻止远端节点进入 React 渲染管线（最根本）
- **L2** 对边缘节点做 `display: none`，保留 DOM 结构但不渲染
- **L3** 对可见但移出视口的视频元素做资源回收

### 9.7 效果预估

| 节点数 | 无优化 | L2+L3（现有） | L1+L2+L3（补全后） |
|--------|--------|---------------|-------------------|
| 50 | 可接受 | 流畅 | 流畅 |
| 100 | 轻微卡顿 | 可接受 | 流畅 |
| 200 | 严重卡顿 | 轻微卡顿 | 流畅 |
| 500+ | 崩溃 | 严重卡顿 | 可接受 |

## 10. IntersectionObserver 内存极限回收

### 10.1 问题

无限画布占用大量内存/显存。视频节点即使不播放，仍可能占用解码器资源。

### 10.2 useVideoElementRecovery Hook

完全移出视口时释放 `<video>` 元素，替换为缩略图；进入视口时恢复。

```typescript
// ui/src/hooks/useVideoElementRecovery.ts

import { useEffect, useRef, useState, useCallback } from 'react';

interface ViewportState {
  isVisible: boolean;
  intersectionRatio: number;
}

type LoadingPhase = 'idle' | 'loading' | 'ready' | 'error';

interface LoadingState {
  phase: LoadingPhase;
  progress: number; // 0-100
}

export function useVideoElementRecovery({
  videoSrc,
  thumbnailSrc,
  autoPlay = false,
}: {
  videoSrc: string | null;
  thumbnailSrc: string | null;
  autoPlay?: boolean;
}) {
  const containerRef = useRef<HTMLDivElement>(null);
  const [viewportState, setViewportState] = useState<ViewportState>({
    isVisible: true,
    intersectionRatio: 1,
  });
  const [showVideo, setShowVideo] = useState(true);
  const [loadingState, setLoadingState] = useState<LoadingState>({
    phase: 'idle',
    progress: 0,
  });
  const videoRef = useRef<HTMLVideoElement | null>(null);

  useEffect(() => {
    const container = containerRef.current;
    if (!container || !videoSrc) return;

    const observer = new IntersectionObserver(
      (entries) => {
        const entry = entries[0];
        const isVisible = entry.isIntersecting;
        const ratio = entry.intersectionRatio;

        setViewportState({ isVisible, intersectionRatio: ratio });

        // 预判区域：即将进入视口时开始预加载
        // rootMargin: '200px' 意味着视口外 200px 就会触发
        if (ratio > 0 && ratio < 0.2 && loadingState.phase === 'idle') {
          setLoadingState({ phase: 'loading', progress: 0 });
        }

        // 完全不可见时，释放视频元素
        if (ratio === 0) {
          setShowVideo(false);
          setLoadingState({ phase: 'idle', progress: 0 });
        }
        // 部分可见或完全可见时，恢复视频元素
        else if (ratio > 0.1) {
          setShowVideo(true);
        }
      },
      {
        threshold: [0, 0.1, 0.5, 1],
        rootMargin: '200px', // 容器外 200px 开始检测
      }
    );

    observer.observe(container);
    return () => observer.disconnect();
  }, [videoSrc]);

  const handleLoadedMetadata = useCallback(() => {
    setLoadingState({ phase: 'ready', progress: 100 });
  }, []);

  const handleCanPlay = useCallback(() => {
    setLoadingState({ phase: 'ready', progress: 100 });
  }, []);

  const handleError = useCallback(() => {
    setLoadingState({ phase: 'error', progress: 0 });
  }, []);

  const handleProgress = useCallback((e: Event) => {
    const target = e.target as HTMLVideoElement;
    if (target.buffered.length > 0) {
      const bufferedEnd = target.buffered.end(0);
      const duration = target.duration;
      if (Number.isFinite(duration) && duration > 0) {
        const progress = Math.round((bufferedEnd / duration) * 100);
        setLoadingState((prev) => ({
          ...prev,
          progress: Math.max(prev.progress, progress),
        }));
      }
    }
  }, []);

  return {
    containerRef,
    viewportState,
    showVideo,
    loadingState,
    videoEventHandlers: {
      onLoadedMetadata: handleLoadedMetadata,
      onCanPlay: handleCanPlay,
      onError: handleError,
      onProgress: handleProgress,
    },
    renderSrc: showVideo ? videoSrc : thumbnailSrc,
    shouldAutoPlay: showVideo && autoPlay && viewportState.intersectionRatio > 0.5,
  };
}
```

## 11. 代理视频 Worker 池（FFmpeg 并发控制）

### 11.1 问题

多个视频节点同时生成 480P 代理版时，FFmpeg 进程满载导致 CPU 100%。

### 11.2 Rust Worker 池实现

```rust
// src-tauri/src/proxy_worker_pool.rs

use std::sync::Arc;
use tokio::sync::{mpsc, Semaphore};
use tokio::task::JoinHandle;

/// 代理生成任务
struct ProxyTask {
    segment_id: String,
    source_path: String,
    proxy_path: String,
    thumbnail_path: String,
    target_resolution: (u32, u32),
    target_fps: u32,
    result_tx: tokio::sync::oneshot::Sender<Result<ProxyResult, ProxyError>>,
}

/// 代理生成结果
#[derive(Debug)]
pub struct ProxyResult {
    pub segment_id: String,
    pub proxy_path: String,
    pub thumbnail_path: String,
}

/// FFmpeg Worker 池
pub struct ProxyWorkerPool {
    task_tx: mpsc::Sender<ProxyTask>,
    semaphore: Arc<Semaphore>,
    workers: Vec<JoinHandle<()>>,
}

impl ProxyWorkerPool {
    /// 创建 Worker 池
    pub fn new(max_concurrent: usize) -> Self {
        let (task_tx, mut task_rx) = mpsc::channel::<ProxyTask>(max_concurrent * 2);
        let semaphore = Arc::new(Semaphore::new(max_concurrent));
        let mut workers = Vec::new();

        for _i in 0..max_concurrent {
            let sem = semaphore.clone();
            let rx = task_rx.clone();
            let worker = tokio::spawn(async move {
                while let Some(mut task) = rx.recv().await {
                    let _permit = sem.acquire().await.unwrap();
                    let result = Self::run_ffmpeg(&task).await;
                    let _ = task.result_tx.send(result).await;
                }
            });
            workers.push(worker);
        }

        Self { task_tx, semaphore, workers }
    }

    /// 提交代理生成任务（自动排队）
    pub async fn submit(&self, task: ProxyTask) -> Result<ProxyResult, ProxyError> {
        match self.semaphore.try_acquire() {
            Ok(_permit) => {
                let (result_tx, result_rx) = mpsc::channel(1);
                let mut task_with_tx = task;
                task_with_tx.result_tx = result_tx;
                self.task_tx.send(task_with_tx).await
                    .map_err(|_| ProxyError::PoolClosed)?;
                result_rx.recv().await.ok_or(ProxyError::WorkerCrashed)?
            }
            Err(_) => {
                Err(ProxyError::QueueFull(
                    "Proxy generation queue full, please wait".to_string()
                ))
            }
        }
    }

    /// 优雅关闭
    pub async fn shutdown(mut self) {
        drop(self.task_tx);
        for worker in self.workers.drain(..) {
            let _ = worker.await;
        }
    }
}
```

## 12. 磁盘空间安全阈值（Disk Space Guard）

### 12.1 问题

视频生成极度消耗存储空间（4K 原片 + 代理 + 多版本），需在操作前检测磁盘可用空间。

### 12.2 阈值配置

| 状态 | 阈值 | 行为 |
|------|------|------|
| Emergency | ≤ 2GB | 阻止新任务启动，已有云端任务继续 |
| Critical | ≤ 5GB | 阻止所有写入操作（下载、代理、保存） |
| Warning | ≤ 10GB | 仅警告，不阻止 |
| Ok | > 10GB | 正常 |

### 12.3 Rust 实现

```rust
// src-tauri/src/disk_space_guard.rs

use std::path::Path;
use sysinfo::Disks;

const DISK_SPACE_WARNING_GB: u64 = 10;
const DISK_SPACE_CRITICAL_GB: u64 = 5;
const DISK_SPACE_EMERGENCY_GB: u64 = 2;

#[derive(Debug, Clone, Copy, PartialEq)]
pub enum DiskSpaceStatus {
    Ok,
    Warning,    // 10GB 以下
    Critical,   // 5GB 以下
    Emergency,  // 2GB 以下
}

pub fn check_disk_space(path: &Path) -> (DiskSpaceStatus, u64) {
    let disks = Disks::new_with_refreshed_list();
    let absolute_path = path.canonicalize().unwrap_or_else(|_| PathBuf::from("/"));

    for disk in disks.list() {
        if absolute_path.starts_with(disk.mount_point()) {
            let available_gb = disk.available_space() / 1024 / 1024 / 1024;
            let status = if available_gb <= DISK_SPACE_EMERGENCY_GB {
                DiskSpaceStatus::Emergency
            } else if available_gb <= DISK_SPACE_CRITICAL_GB {
                DiskSpaceStatus::Critical
            } else if available_gb <= DISK_SPACE_WARNING_GB {
                DiskSpaceStatus::Warning
            } else {
                DiskSpaceStatus::Ok
            };
            return (status, available_gb);
        }
    }

    (DiskSpaceStatus::Ok, u64::MAX)
}
```

### 12.4 自动恢复机制

```rust
pub struct DiskSpaceMonitor {
    is_paused: Arc<AtomicBool>,
    check_interval: Duration,
}

impl DiskSpaceMonitor {
    pub async fn start(&self) {
        let app_data_dir = paths::app_data_dir();
        loop {
            sleep(self.check_interval).await;
            let (status, _) = check_disk_space(&app_data_dir);
            match status {
                DiskSpaceStatus::Emergency => {
                    self.is_paused.store(true, Ordering::SeqCst);
                    tracing::warn!("Disk space emergency, pausing new tasks");
                }
                _ => {
                    if self.is_paused.load(Ordering::SeqCst) {
                        self.is_paused.store(false, Ordering::SeqCst);
                        tracing::info!("Disk space recovered, resuming tasks");
                    }
                }
            }
        }
    }
}
```

## 16. Tauri Asset 协议适配

### 16.1 路径解析

前端用 `convertFileSrc` 加载 `{app_data_dir}` 下文件时，WebView 实际走 `http://asset.localhost/...`，由 Tauri asset 协议读盘。

- **相对路径**：须先 `resolve_app_data_media_path`；前端优先 `api.mediaSrcFromAppDataRelative`（resolve 失败时可回退原路径再 convert）
- **Windows 路径形态**：使用 `dunce::canonicalize`（避免裸 `std::fs::canonicalize` 产生的 `\\?\` 前缀与 scope 匹配不一致）

### 16.2 Asset Scope 放行

在 `main.rs` 的 `setup` 里对当前运行时 `paths::app_data_dir()` 调用：

```rust
app.state::<tauri::Scopes>().allow_directory(&app_data_dir, true)
```

把实际应用数据根递归加入 asset scope。成功时启动日志有 `startup: allowed app_data_dir in asset scope`。

**注意**：不要依赖 `tauri.conf.json` 里 `$EXE/../../../data/**` 这类带 `..` 的静态 scope —— Tauri `PathResolver::parse` 会丢弃 `..` 段。
