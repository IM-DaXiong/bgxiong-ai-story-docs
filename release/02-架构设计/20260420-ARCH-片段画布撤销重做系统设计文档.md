# 片段画布 Ctrl+Z / Ctrl+Y 撤销重做系统 — 开发设计文档

> 版本：v1.2 · 2026-04-20 · 基于 `SegmentCanvasTab.tsx` 现有架构（§15 为落地对照）

---

## 0. 目标

为片段画布（`SegmentCanvasTab`）实现 **≥50 步历史快照** 的撤销/重做系统，支持：

- **Ctrl+Z**（macOS: Cmd+Z）撤销最近操作
- **Ctrl+Y**（macOS: Cmd+Shift+Z）重做已撤销操作
- **Ctrl+Shift+Z** 等价重做（兼容 Windows）

用户可感知的画布操作（节点拖拽、连线增删、节点增删、视口平移/缩放/重置布局、确认参考图引用）均纳入历史栈；纯 UI 临时态（悬停高亮、右键菜单位置等）不纳入。

## 1. 现状分析

### 1.1 可变画布状态一览

| 状态变量 | 类型 | 持久化 | 撤销/重做是否纳入 |
|---|---|---|---|
| `tilePositions` | `Record<string,{x,y}>` | localStorage (`useCanvasPersist`) | ✅ 节点位置 |
| `placementOrder` | `string[]` | localStorage (`placementStorageKey`) | ✅ 节点顺序 |
| `independentTransitions` | `unknown[]` | localStorage (按 storyId: `segment_canvas_independent_transitions_v1_{storyId}`) | ✅ 连线/转场 |
| `viewport` (`panX, panY, scale`) | `CanvasViewport` | localStorage (`useCanvasPersist`) | ✅ 视口状态 |
| `isDraggingSegmentTileRef` | `boolean` (ref) | 无 | ❌ 拖拽中间态标志 |
| `selectedCanvasNodeIds` | `Set<string>` | 无 | ❌ 仅 UI 选中态 |
| `connectFromNodeId` | `string\|null` | 无 | ❌ 拖连线中间态 |
| `linkDrag` | object\|null | 无 | ❌ 拖连线中间态 |
| `canvasContextMenu` | object\|null | 无 | ❌ 右键菜单 |
| `clipFwDoc` / `clipFwRevision` | 业务数据 | Tauri 命令 | ❌ 服务端数据，画布不撤销 |
| `refPadPreviewById` | `Record<string,string>` | 无 | ❌ 仅预览缓存 |

**派生数据**（不在快照内，随源状态恢复自动重建）：
- `canvasDataNodes`：由 `placementOrder` + `allCandidateNodes` + `segments` + `effectiveStoryboardShotsForFilterScene` 经 `useMemo` 派生。撤销时随 `placementOrder` 恢复自动重建。

### 1.2 当前状态变更入口（需拦截的操作）

| # | 操作 | 触发方式 | 修改的状态 | 备注 |
|---|---|---|---|---|
| 1 | **节点拖拽结束** | `InfiniteCanvas` → `onAllNodePositionsCommit` | `tilePositions` | — |
| 2 | **创建连线** | 端口拖拽 → `connectToInputPort` | `independentTransitions` | — |
| 3 | **删除连线**（detach 拖离 ≥10px 到空白 / 右键删除边） | 手势（从占用输入口拖离 ≥ `DETACH_CANCEL_ARM_THRESHOLD_PX`）/ 菜单 | `independentTransitions` | detach 场景含重连/取消两种子分支 |
| 4 | **添加节点**（「创建独立片段」「加入分镜」弹窗确认） | 菜单 / 弹窗 | `placementOrder`, `tilePositions` | 创建 `seg:` / `fw:` / `sb:` 节点 |
| 5 | **删除/移除节点**（「从画布移除」「删除节点」） | 右键菜单 | `placementOrder`, `tilePositions`, `selectedCanvasNodeIds` | — |
| 6 | **移除参考图节点（rpad:）** | 右键菜单 | `placementOrder`, `tilePositions`, 后端片段正文参考图引用 | ⚠️ 含异步 `api.updateNode` |
| 7 | **确认参考图引用** | `commitSegmentReferencePads`（「管理参考图」弹窗确认） | `placementOrder`, `tilePositions` | 插入 `rpad:` 节点 |
| 8 | **视口平移/缩放** | `applyViewport` / 小地图拖动 / 缩放按钮 | `viewport` | — |
| 9 | **重置布局** | 右键菜单 → `resetCanvasLayout` | `viewport`, `tilePositions`，同时设置 `hasHydratedPersistRef = true` | — |
| 10 | **框选后批量删除** | 框选 + 右键菜单 | `placementOrder`, `tilePositions`, `selectedCanvasNodeIds` | — |

**不纳入历史栈的操作**：`executeSyncFromFramework`（同步片段框架到库）— 仅修改片段库数据，画布 `placement` 由自动 sync effect 处理，不产生快照。

### 1.3 不可变 / 不纳入历史栈的数据

- 服务端节点内容（标题、提示词等）— 用户可在右侧面板 Ctrl+Z，但那是文本字段的撤销，不属于画布层
- 右键菜单、连线拖拽中间态、弹窗状态 — 纯 UI 临时态
- `clipFramework` 文档 — 服务端数据
- `refPadPreviewById` — 仅图片预览缓存
- `rpad:` 节点自动同步 effect（依赖 `padRefIdsSyncKey`）产生的 placement 变更不单独产生快照（其变更由用户操作如 `commitSegmentReferencePads` 或 `removeTilesFromSegmentCanvas` 触发，已在对应操作入口捕获）

## 2. 架构设计

### 2.1 核心模型：快照式历史栈

选择 **全量快照（Snapshot）** 而非 Command Pattern，理由：

1. 片段画布的 `tilePositions` / `independentTransitions` / `placementOrder` 总数据量极小（通常 <50 节点，<10 条边），快照 JSON < 10KB，50 步总计 < 500KB，内存和存储零压力。
2. 快照式实现简单、无边界效应，不存在 Command 逆函数遗漏风险。
3. 与现有 `useCanvasPersist` / `localStorage` 持久化机制天然兼容。

### 2.2 快照数据结构

```typescript
interface SegmentCanvasSnapshot {
  /** 节点位置（世界坐标） */
  tilePositions: Record<string, { x: number; y: number }>;
  /** 节点手动缩放（右下角 resize；与 `useCanvasPersist` tileSizes 一致） */
  tileSizes: Record<string, { w: number; h: number }>;
  /** 节点排列顺序（决定画布节点列表顺序） */
  placementOrder: string[];
  /** 独立转场连线（与 localStorage 一致的 JSON 数组） */
  independentTransitions: unknown[];
  /** 视口状态 */
  viewport: CanvasViewport;
  /** 可选：快照产生原因（用于 UI 提示，如"拖拽节点"） */
  label?: string;
}
```

**注意**：`tilePositions` 在撤销恢复后可能包含不在当前 `canvasDataNodes` 中的节点 ID（"幽灵"坐标）。这是容许的，因为后续 `canvasDataNodes` 变化时 layout sync effect 会自动清理。

### 2.3 历史栈数据结构

```typescript
interface UndoRedoState {
  /** 过去状态（index 0 = 最早，末尾 = 最近一次操作前） */
  undoStack: SegmentCanvasSnapshot[];
  /** 未来状态（被撤销、可重做的操作） */
  redoStack: SegmentCanvasSnapshot[];
}
```

**容量**：`undoStack` 最大 **50 步**。`redoStack` 最大 50 步。超出时从栈底丢弃。

> `isApplying` **不作为快照结构字段**，仅在 Hook 内部用 `useRef` 管理，防止 `applySnapshot` 触发 React effect 产生额外快照。

### 2.4 撤销/重做流程

```
           操作发生
              │
              ▼
     ┌─ pushSnapshot(before) ─┐
     │  保存操作前快照到 undoStack   │
     │  清空 redoStack              │
     │  isApplying = false          │
     └─────────────────────────────┘
              │
              ▼
        状态已变更（React setState + localStorage 同步完成）

--- Ctrl+Z 撤销 ---
     1. pop from undoStack → prevSnapshot
     2. push 当前状态到 redoStack
     3. applySnapshot(prevSnapshot) → setState + persistSync
     4. isApplying = true（期间抑制 effect 自动快照）
     5. 待 setState flush 后 isApplying = false

--- Ctrl+Y / Ctrl+Shift+Z 重做 ---
     同上方向相反
```

### 2.5 视口变更的合并策略

**问题**：视口平移/缩放产生极高频事件（每次滚轮 `onViewportChange` 都触发），若每次都推快照，50 步历史在用户滚动几下后就会耗尽。

**解决方案：视口快照合并窗口**

- 视口变更 **仅在以下时刻产生快照**：
  1. 拖拽节点结束时（`onAllNodePositionsCommit`）— 此时视口与位置一同快照
  2. 连线增删时
  3. 节点增删时
  4. 重置布局时
  5. **用户停止平移/缩放 1500ms 后**（视口空闲定时器）
- 视口空闲定时器发出快照时，只记录视口变更前的状态（不含 tile 变更）
- 如果两次视口快照之间无 tile/edge/placement 变更，仅保留**最后一次**视口快照（合并前 N 次纯视口变更为一步）

**实现**：视口变更使用 `viewportIdleTimerRef`（`setTimeout` 1500ms），到期时 `pushSnapshot`。`undoStack` 合并逻辑：若栈顶快照与即将推入的快照**仅在 `viewport` 上有差异**，则替换栈顶的 `viewport`（合并为一步），而非推入新快照。

### 2.6 `isApplying` 标志 — 防止撤销/重做过程中二次快照

`applySnapshot()` 调用 `setTilePositions` / `setPlacementOrder` / `setIndependentTransitions` / `applyViewport`，这些变更会触发 React effect（如 layout sync effect、selection cleanup effect）。若 effect 中或其后继逻辑产生快照，会污染历史栈。

**解决**：Hook 内部维护 `isApplyingRef`（`useRef<boolean>`）。所有 `pushSnapshot` / `pushViewportChange` 调用先检查 `isApplyingRef.current`，为 `true` 时跳过。

**时序细节**（关键）：`undo`/`redo` 中，`isApplyingRef.current = true` → 采集当前状态 → `applySnapshot` → **用 `requestAnimationFrame` 延迟 `isApplyingRef.current = false`**，确保 React effect 有足够时间运行且被 `isApplying` 抑制后再恢复。

### 2.7 `applySnapshot` 内部更新顺序（强制）

为避免 `applyViewport` 内 `persistSync(vp, tilePositionsRef.current)` 写入**旧** tilePositions，`applySnapshot` 必须严格遵守以下顺序：

1. **先更新所有 ref**（`tilePositionsRef.current` / `placementOrderRef.current` / `independentTransitionsRef.current` / `viewportRef.current`）
2. **再调用 setState / 包装函数**（此时 ref 已是快照值）
3. **最后写入 localStorage 补充键**（`placementStorageKey`、`independentTransitionsStorageKey`）

```typescript
// 正确顺序：
tilePositionsRef.current = snapshot.tilePositions;    // 1. ref 先行
placementOrderRef.current = snapshot.placementOrder;
independentTransitionsRef.current = snapshot.independentTransitions;
viewportRef.current = snapshot.viewport;

setTilePositions(snapshot.tilePositions);             // 2. setState（此时 ref 已是新值）
setPlacementOrder(snapshot.placementOrder);
setIndependentTransitions(snapshot.independentTransitions);
setViewport(snapshot.viewport);                         // 内部调用 applyViewport → persistSync(vp, tilePositionsRef.current) — 此时 ref 已是快照值 ✓

// 3. 补充 localStorage（placementOrder 和 independentTransitions）
//    useCanvasPersist 管理的 tilePositions + viewport 已由 persistSync 写入
```

## 3. Hook 设计 — 包装 Setter 模式（可插拔）

### 3.0 可插拔设计原则

**核心思路**：Hook 提供一组**包装过的 setter**（`setTilePositions`、`setPlacementOrder`、`setIndependentTransitions`、`applyViewport`），业务代码将原有的 setter 调用替换为 hook 提供的版本。**无需**在每个业务函数内部手动插入 `pushSnapshot`。

**侵入性对比**：

| 方式 | 改动点 | 侵入性 |
|------|--------|--------|
| 手动 `pushSnapshot`（旧方案） | ~10 个函数内部各加 1-2 行 | 高 — 散布在业务逻辑中，容易遗漏或错位 |
| **包装 Setter（本方案）** | 每个 setter 调用处替换为 hook 版本 | **低** — 单行替换，语义等价，不改变原有控制流 |

**自动快照机制**：包装 setter 在调用真实 setState **之前**自动采集快照。若调用发生在 `isApplying` 期间（撤销/重做内部），自动跳过。

**对原有业务逻辑的影响**：包装 setter **仅**在真实 setState 前加快照采集，不改变原有 setState 的参数、返回值、副作用（`persistSync`、`persistPlacementOrder` 等均在原有位置执行，hook 不拦截这些 side effect）。

### 3.1 `useSegmentCanvasUndoRedo`

```typescript
// ui/src/hooks/useSegmentCanvasUndoRedo.ts

interface UseUndoRedoOptions {
  /** 画布持久化 key，变化时清空历史栈 */
  persistKey: string;
  /** 当前故事 ID，用于写入 independentTransitions 的 localStorage 键 */
  storyId: string | undefined;
  /** 最大撤销步数（默认 50） */
  maxSteps?: number;
  /** 业务传入的 4 个 ref，用于采集/恢复快照 */
  refs: {
    tilePositionsRef: React.MutableRefObject<Record<string, { x: number; y: number }>>;
    placementOrderRef: React.MutableRefObject<string[]>;
    independentTransitionsRef: React.MutableRefObject<unknown[]>;
    viewportRef: React.MutableRefObject<CanvasViewport>;
  };
  /** 业务原有的 4 个 setState，hook 包装后返回 */
  setters: {
    setTilePositions: React.Dispatch<React.SetStateAction<Record<string, { x: number; y: number }>>>;
    setPlacementOrder: React.Dispatch<React.SetStateAction<string[]>>;
    setIndependentTransitions: React.Dispatch<React.SetStateAction<unknown[]>>;
    setViewport: React.Dispatch<React.SetStateAction<CanvasViewport>>;
  };
  /** 是否处于节点拖拽中（用于抑制拖拽期间的视口快照） */
  isDragging?: () => boolean;
}

interface UndoRedoActions {
  /** 撤销一步 */
  undo: () => void;
  /** 重做一步 */
  redo: () => void;
  /** 是否可撤销 */
  canUndo: boolean;
  /** 是否可重做 */
  canRedo: boolean;
  /** 包装后的 setTilePositions — 替换原有调用即可自动快照 */
  setTilePositions: React.Dispatch<React.SetStateAction<Record<string, { x: number; y: number }>>>;
  /** 包装后的 setPlacementOrder — 替换原有调用即可自动快照 */
  setPlacementOrder: React.Dispatch<React.SetStateAction<string[]>>;
  /** 包装后的 setIndependentTransitions — 替换原有调用即可自动快照 */
  setIndependentTransitions: React.Dispatch<React.SetStateAction<unknown[]>>;
  /** 包装后的 applyViewport — 替换原有调用即可自动快照 */
  applyViewport: (vp: CanvasViewport) => void;
  /** 手动推入快照（极少需要，用于需要在 setState 之前显式快照的特殊场景） */
  pushSnapshot: (label?: string) => void;
  /** 当前是否在应用快照（供 effect 判断是否抑制自动快照） */
  isApplying: boolean;
}

function useSegmentCanvasUndoRedo(options: UseUndoRedoOptions): UndoRedoActions;
```

### 3.2 包装 Setter 实现逻辑

每个包装 setter 的内部流程（以 `setTilePositions` 为例）：

```typescript
// 包装 setTilePositions — 自动在 setState 前采集快照
const undoSetTilePositions: typeof setTilePositions = useCallback((updater) => {
  // 1. 始终调用真实 setState（不可跳过，否则状态不会变更）
  // 2. 仅控制是否采集快照
  if (isApplyingRef.current) {
    // 撤销/重做应用中：直接 setState，不采集快照（避免递归）
    setters.setTilePositions(updater);
    return;
  }
  // 批量模式：跳过快照采集，但仍调用真实 setState
  if (batchStartRef.current !== null) {
    setters.setTilePositions(updater);
    return;
  }
  // 正常操作：采集快照后再 setState
  const snapshot = collectSnapshot();
  doPushSnapshot(snapshot, "tile_change");
  setters.setTilePositions(updater);
  // 清除视口空闲定时器（此快照已包含视口）
  if (viewportIdleTimerRef.current) {
    clearTimeout(viewportIdleTimerRef.current);
    viewportIdleTimerRef.current = null;
  }
}, [...]);
```

**关键安全规则（强制）**：

1. **包装 setter 永远调用真实 setState**，不得 `return` 跳过状态变更——否则业务逻辑中断
2. **快照采集发生在 setState 之前**——此时 ref 仍是旧值，快照记录的是操作前状态
3. **不拦截原 setter 副作用**——如 `setPlacementOrder` 内部的 `persistPlacementOrder(next)` 照常执行

### 3.2.1 包装 applyViewport（带视口合并）

`applyViewport` 除自动快照外，还支持**视口空闲合并**（1500ms 后纯视口变更与栈顶合并为一步）：

```typescript
const undoApplyViewport = useCallback((vp: CanvasViewport) => {
  // 始终应用视口
  setters.setViewport(vp);
  viewportRef.current = vp;
  persistSync(vp, refs.tilePositionsRef.current);

  // 正常操作时安排视口快照（空闲后）
  if (!isApplyingRef.current && batchStartRef.current === null) {
    scheduleViewportSnapshot();
  }
}, [...]);
```

`scheduleViewportSnapshot` 内部使用 `viewportIdleTimerRef` 做 1500ms 防抖，到期时检查：
- 若 `isApplyingRef` 为 true → 跳过
- 若拖拽中（`isDragging?.()`）→ 跳过
- 若栈顶已是 `"viewport"` label 且非视口字段未变 → **替换栈顶**（合并）
- 否则 → 推入新快照

### 3.3 Context 与消费

Hook 返回 4 个包装 setter + `undo` / `redo` + `canUndo` / `canRedo` + `pushSnapshot`。业务代码中**只需做 setter 替换**：

```diff
// 变更 1：替换 4 个 setter 为 undoRedo 包装版本
- setTilePositions(prev => ({ ...prev, ...positions }));
+ undoRedo.setTilePositions(prev => ({ ...prev, ...positions }));

- setPlacementOrder(next);
+ undoRedo.setPlacementOrder(next);

- setIndependentTransitions(next);
+ undoRedo.setIndependentTransitions(next);

- setViewport(vp);
+ undoRedo.setViewport(vp); // 或 undoRedo.applyViewport(vp)

// 变更 2：特殊操作前手动快照（label 用于 UI 显示）
- function resetCanvasLayout() { ... }
+ function resetCanvasLayout() { undoRedo.pushSnapshot("reset_layout"); ... }

+ function confirmAddStoryboardShots() { undoRedo.pushSnapshot("add_shots"); ... }

// 变更 3：批量操作（框选多个节点删除）
- function batchRemove() { for (id of ids) removeTilesFromSegmentCanvas([id]); }
+ function batchRemove() {
+   undoRedo.beginBatch();
+   for (id of ids) removeTilesFromSegmentCanvas([id]);
+   undoRedo.commitBatch("batch_remove");
+ }

// 变更 4：effect 中抑制自动快照
- useEffect(() => { /* layout sync */ }, [canvasDataNodes]);
+ useEffect(() => { if (undoRedo.isApplying) return; /* layout sync */ }, [canvasDataNodes, undoRedo.isApplying]);
```

**无需修改的**：
- 原有 `persistSync` / `persistPlacementOrder` / `persistTransitions` 调用位置不变
- 原有 `tilePositionsRef.current = ...` 同步逻辑不变
- 原有 React effect 依赖关系不变（除新增 `undoRedo.isApplying` 抑制项）
- 所有业务函数内部逻辑完全不变——undo/redо 对业务透明

### 3.4 快照 label 清单

下表列出所有手动快照（`pushSnapshot`）的 label，用于 UI 显示及视口合并判断：

| label | 触发操作 |
|---|---|
| `"tile_change"` | 包装 setter 自动，节点拖拽/增删位置等 |
| `"drag"` | 同 tile_change（onAllNodePositionsCommit 专用 label） |
| `"add_edge"` | 连线创建 |
| `"reconnect_edge"` | 连线重连 |
| `"delete_edge"` | 连线删除 |
| `"create_node"` | 创建独立片段 |
| `"add_shots"` | 添加分镜 |
| `"remove_node"` | 移除片段（非 rpad） |
| `"remove_ref_pad"` | 移除参考图节点（rpad，含异步后端操作） |
| `"confirm_ref_pads"` | 确认参考图引用 |
| `"remove_from_framework"` | 从框架移除 |
| `"reset_layout"` | 重置布局 |
| `"batch_remove"` | 框选批量移除 |
| `"viewport"` | 视口空闲后自动快照 |

自动快照（通过包装 setter）使用通用 `"tile_change"` / `"placement_change"` / `"transition_change"` label；特殊操作通过手动 `pushSnapshot` 覆盖 label。

### 3.5 实现伪代码（核心逻辑，与 §3.1 接口一致）

```typescript
function useSegmentCanvasUndoRedo({
  persistKey,
  storyId,
  maxSteps = 50,
  refs,          // tilePositionsRef / placementOrderRef / independentTransitionsRef / viewportRef
  setters,       // setTilePositions / setPlacementOrder / setIndependentTransitions / setViewport
  isDragging,    // () => boolean
}: UseUndoRedoOptions): UndoRedoActions {
  const undoStackRef = useRef<SegmentCanvasSnapshot[]>([]);
  const redoStackRef = useRef<SegmentCanvasSnapshot[]>([]);
  const isApplyingRef = useRef(false);
  const viewportIdleTimerRef = useRef<ReturnType<typeof setTimeout> | null>(null);
  const batchStartRef = useRef<SegmentCanvasSnapshot | null>(null);

  const [canUndo, setCanUndo] = useState(false);
  const [canRedo, setCanRedo] = useState(false);
  const updateCanFlags = useCallback(() => {
    setCanUndo(undoStackRef.current.length > 0);
    setCanRedo(redoStackRef.current.length > 0);
  }, []);

  // -- 快照采集（读 ref 当前值） --
  const collectSnapshot = useCallback((): SegmentCanvasSnapshot => ({
    tilePositions: { ...refs.tilePositionsRef.current },
    placementOrder: [...refs.placementOrderRef.current],
    independentTransitions: JSON.parse(JSON.stringify(refs.independentTransitionsRef.current)),
    viewport: { ...refs.viewportRef.current },
  }), [refs]);

  // -- 推入快照（内部用） --
  const doPushSnapshot = useCallback((snapshot: SegmentCanvasSnapshot, label?: string) => {
    if (isApplyingRef.current) return;
    if (batchStartRef.current !== null) return; // 批量期间跳过
    snapshot.label = label;
    undoStackRef.current.push(snapshot);
    if (undoStackRef.current.length > maxSteps) undoStackRef.current.shift();
    redoStackRef.current = [];
    if (viewportIdleTimerRef.current) {
      clearTimeout(viewportIdleTimerRef.current);
      viewportIdleTimerRef.current = null;
    }
    updateCanFlags();
  }, [maxSteps, updateCanFlags]);

  // -- 手动推入快照（用于 resetLayout 等特殊操作，需在 setState 之前调用） --
  const pushSnapshot = useCallback((label?: string) => {
    doPushSnapshot(collectSnapshot(), label);
  }, [collectSnapshot, doPushSnapshot]);

  // -- 视口空闲定时器（1500ms 防抖，合并纯视口快照） --
  const scheduleViewportSnapshot = useCallback(() => {
    if (isApplyingRef.current) return;
    if (isDragging?.()) return; // 拖拽中不推
    if (viewportIdleTimerRef.current) clearTimeout(viewportIdleTimerRef.current);
    viewportIdleTimerRef.current = setTimeout(() => {
      if (isApplyingRef.current || isDragging?.()) return;
      const snapshot = collectSnapshot();
      snapshot.label = "viewport";
      // 若栈顶已是 viewport 快照且非视口字段一致，合并为一步
      const top = undoStackRef.current[undoStackRef.current.length - 1];
      if (top && top.label === "viewport" &&
          JSON.stringify(top.tilePositions) === JSON.stringify(snapshot.tilePositions) &&
          JSON.stringify(top.placementOrder) === JSON.stringify(snapshot.placementOrder) &&
          JSON.stringify(top.independentTransitions) === JSON.stringify(snapshot.independentTransitions)) {
        undoStackRef.current[undoStackRef.current.length - 1] = snapshot;
        updateCanFlags();
        return;
      }
      doPushSnapshot(snapshot, "viewport");
    }, 1500);
  }, [collectSnapshot, isDragging, doPushSnapshot, updateCanFlags]);

  // -- 批量操作 --
  const beginBatch = useCallback(() => {
    batchStartRef.current = collectSnapshot();
  }, [collectSnapshot]);

  const commitBatch = useCallback((label?: string) => {
    if (batchStartRef.current === null) return;
    batchStartRef.current.label = label;
    undoStackRef.current.push(batchStartRef.current);
    if (undoStackRef.current.length > maxSteps) undoStackRef.current.shift();
    redoStackRef.current = [];
    batchStartRef.current = null;
    if (viewportIdleTimerRef.current) {
      clearTimeout(viewportIdleTimerRef.current);
      viewportIdleTimerRef.current = null;
    }
    updateCanFlags();
  }, [maxSteps, updateCanFlags]);

  // -- 包装 setTilePositions --
  const undoSetTilePositions: typeof setters.setTilePositions = useCallback((updater) => {
    if (isApplyingRef.current) {
      setters.setTilePositions(updater); // 撤销/重做中仅执行 setState，不快照
      return;
    }
    if (batchStartRef.current !== null) {
      setters.setTilePositions(updater); // 批量中执行 setState，快照由 beginBatch 负责
      return;
    }
    doPushSnapshot(collectSnapshot(), "tile_change");
    setters.setTilePositions(updater);
    if (viewportIdleTimerRef.current) {
      clearTimeout(viewportIdleTimerRef.current);
      viewportIdleTimerRef.current = null;
    }
  }, [setters, collectSnapshot, doPushSnapshot]);

  // -- 包装 setPlacementOrder --
  const undoSetPlacementOrder: typeof setters.setPlacementOrder = useCallback((updater) => {
    if (isApplyingRef.current) { setters.setPlacementOrder(updater); return; }
    if (batchStartRef.current !== null) { setters.setPlacementOrder(updater); return; }
    doPushSnapshot(collectSnapshot(), "placement_change");
    setters.setPlacementOrder(updater);
    if (viewportIdleTimerRef.current) {
      clearTimeout(viewportIdleTimerRef.current);
      viewportIdleTimerRef.current = null;
    }
  }, [setters, collectSnapshot, doPushSnapshot]);

  // -- 包装 setIndependentTransitions --
  const undoSetIndependentTransitions: typeof setters.setIndependentTransitions = useCallback((updater) => {
    if (isApplyingRef.current) { setters.setIndependentTransitions(updater); return; }
    if (batchStartRef.current !== null) { setters.setIndependentTransitions(updater); return; }
    doPushSnapshot(collectSnapshot(), "transition_change");
    setters.setIndependentTransitions(updater);
    if (viewportIdleTimerRef.current) {
      clearTimeout(viewportIdleTimerRef.current);
      viewportIdleTimerRef.current = null;
    }
  }, [setters, collectSnapshot, doPushSnapshot]);

  // -- 包装 setViewport（由 applyViewport 内部调用） --
  const undoSetViewport = useCallback((vp: CanvasViewport) => {
    refs.viewportRef.current = vp;
    setters.setViewport(vp);
    scheduleViewportSnapshot();
  }, [refs, setters, scheduleViewportSnapshot]);

  // -- 撤销 --
  const undo = useCallback(() => {
    if (undoStackRef.current.length === 0) return;
    isApplyingRef.current = true;
    const prev = undoStackRef.current.pop()!;
    redoStackRef.current.push(collectSnapshot());
    // 直接写 ref + setState（绕过包装 setter，避免再次快照）
    refs.tilePositionsRef.current = prev.tilePositions;
    refs.placementOrderRef.current = prev.placementOrder;
    refs.independentTransitionsRef.current = prev.independentTransitions;
    refs.viewportRef.current = prev.viewport;
    setters.setTilePositions(prev.tilePositions);
    setters.setPlacementOrder(prev.placementOrder);
    setters.setIndependentTransitions(prev.independentTransitions);
    setters.setViewport(prev.viewport);
    // 补充 localStorage
    try { localStorage.setItem(persistKey, JSON.stringify({ viewport: prev.viewport, tilePositions: prev.tilePositions })); } catch {}
    try { localStorage.setItem(`${persistKey}__placements_v1`, JSON.stringify(prev.placementOrder)); } catch {}
    if (storyId) {
      try { localStorage.setItem(`segment_canvas_independent_transitions_v1_${storyId}`, JSON.stringify(prev.independentTransitions)); } catch {}
    }
    // rAF 后放行 isApplying，确保 React effect 运行时被抑制
    requestAnimationFrame(() => { isApplyingRef.current = false; });
    updateCanFlags();
  }, [collectSnapshot, persistKey, storyId, refs, setters, updateCanFlags]);

  // -- 重做 --
  const redo = useCallback(() => {
    if (redoStackRef.current.length === 0) return;
    isApplyingRef.current = true;
    const next = redoStackRef.current.pop()!;
    undoStackRef.current.push(collectSnapshot());
    refs.tilePositionsRef.current = next.tilePositions;
    refs.placementOrderRef.current = next.placementOrder;
    refs.independentTransitionsRef.current = next.independentTransitions;
    refs.viewportRef.current = next.viewport;
    setters.setTilePositions(next.tilePositions);
    setters.setPlacementOrder(next.placementOrder);
    setters.setIndependentTransitions(next.independentTransitions);
    setters.setViewport(next.viewport);
    try { localStorage.setItem(persistKey, JSON.stringify({ viewport: next.viewport, tilePositions: next.tilePositions })); } catch {}
    try { localStorage.setItem(`${persistKey}__placements_v1`, JSON.stringify(next.placementOrder)); } catch {}
    if (storyId) {
      try { localStorage.setItem(`segment_canvas_independent_transitions_v1_${storyId}`, JSON.stringify(next.independentTransitions)); } catch {}
    }
    requestAnimationFrame(() => { isApplyingRef.current = false; });
    updateCanFlags();
  }, [collectSnapshot, persistKey, storyId, refs, setters, updateCanFlags]);

  // -- 清空历史（persistKey 变更时） --
  useEffect(() => {
    undoStackRef.current = [];
    redoStackRef.current = [];
    batchStartRef.current = null;
    if (viewportIdleTimerRef.current) clearTimeout(viewportIdleTimerRef.current);
    updateCanFlags();
  }, [persistKey, updateCanFlags]);

  // -- 组件卸载清理 --
  useEffect(() => {
    return () => {
      if (viewportIdleTimerRef.current) clearTimeout(viewportIdleTimerRef.current);
    };
  }, []);

  return {
    undo, redo, canUndo, canRedo,
    setTilePositions: undoSetTilePositions,
    setPlacementOrder: undoSetPlacementOrder,
    setIndependentTransitions: undoSetIndependentTransitions,
    applyViewport: undoSetViewport,
    pushSnapshot,
    beginBatch,
    commitBatch,
    get isApplying() { return isApplyingRef.current; },
  };
}
```

      undoRedo.redo();

**副作用说明**：`resetCanvasLayout` 设置 `hasHydratedPersistRef.current = true` 禁止后续从 `persistInitial` 合并瓦片。撤销会恢复旧的 `tilePositions`，但该 flag 保持 `true`。这是可接受的——撤销后 tile 位置已正确恢复，flag 不会立即产生副作用（仅在下次切换 `canvasPersistKey` 等场景才可能影响 hydrate 逻辑）。

## 8. 边界情况与决策

| 场景 | 决策 | 理由 |
|---|---|---|
| 撤销「创建独立片段」 | 仅从画布移除瓦片，不删除后端节点 | 防止数据丢失；用户可重新添加 |
| 撤销「添加分镜」 | 仅移除画布上的引用/瓦片，不删除分镜节点 | 同上 |
| 撤销「删除节点」 | 恢复瓦片位置与排列，但若后端已删除则仍显示（`canvasDataNodes` 派生时若找不到数据则走 fallback） | 后端 `deleteNode` 不可逆；快照仅恢复画布层 |
| 撤销「移除参考图（rpad）」 | 恢复画布层（`placementOrder` 恢复 `rpad:` id + 坐标），**不恢复后端片段正文参考图引用** | 后端 `api.updateNode` 已写盘；若需恢复可扩展快照记录 `restoredPadRefs` |
| 撤销「删除连线」 | 完全可逆——恢复 `independentTransitions` 即可 | 转场连线完全在 localStorage |
| 撤销「断开占用输入口（detach 取消）」 | 完全可逆——恢复旧边即可 | `targetInputPortIndex` 随 `independentTransitions` 整体恢复 |
| 后端节点内容变更（如编辑提示词） | 不纳入画布撤销栈 | 属于文本编辑撤销，不在画布层 |
| 切换场次/故事 | 清空 `undoStack` / `redoStack` | 不同作用域的画布状态独立（`canvasPersistKey` 变化触发） |
| 画布为空时撤销 | 无操作 + Toast 提示 | 栈空不可撤销 |
| `resetCanvasLayout` 副作用 | `hasHydratedPersistRef = true` 不在快照内 | 撤销后 tile 位置已正确恢复，flag 无立即副作用 |
| `executeSyncFromFramework` | 不纳入历史栈 | 仅修改片段库数据，画布 placement 由 sync effect 处理 |
| 撤销后 `InfiniteCanvas` 拖拽状态 | `applySnapshot` 直接更新 state/ref，不走 `InfiniteCanvas` 拖拽路径，不触发 `onDragStateChange` | 无需额外处理 |
| 新操作清空 redo | 标准 undo/redo 语义：新 `pushSnapshot` 清空 `redoStack` | — |

## 9. 性能考量

| 指标 | 估算 | 说明 |
|---|---|---|
| 单快照大小 | ~5–10 KB | 50 节点 × (id + x + y) + 10 条边 + 视口（`independentTransitions` 含 `targetInputPortIndex`） |
| 50 步总内存 | ~250–500 KB | 浏览器完全可承受 |
| 深拷贝耗时 | <0.5 ms | 推荐 `structuredClone`，兼容不支持时回退 `JSON.parse(JSON.stringify)` |
| 推入快照频率 | 低频（拖拽/连线/增删等用户操作，非每帧） | 不影响交互帧率 |
| 视口快照合并 | 1500ms 防抖后推入，相同 tile/transitions/placement 时仅替换栈顶 | 视口连续变更不会快速消耗栈 |
| `requestAnimationFrame` 延迟 | +1 帧 | `isApplying` 恢复延迟，确保 effect 被抑制后放行 |

## 14. 扩展性预留

- **`SegmentCanvasSnapshot.label`** 已用于 Undo/Redo Toast（`segmentCanvasUndoToast` / `segmentCanvasRedoToast` + `segmentCanvasHistoryLabel*`，见 §15）。
- **批量操作 API**（`beginBatch` / `commitBatch`）已设计，支持多步操作合并为一步撤销；**当前落地**未实现该 API，而以显式 `checkpoint` + 防抖为主（§15）。
- **后端联动**：快照结构可扩展 `restoredPadRefs` 字段，支持「撤销移除参考图时同时恢复后端片段正文参考图引用」等场景；扩展 `deletedNodeIds` 字段，支持「撤销创建时同时删除后端节点」。
- **跨 Tab 撤销**：当前设计为单画布会话内撤销；跨 Tab（如从角色页切到片段页）的历史栈不互通。

### 15.1 实现方式

| 设计文档章节 | 规划方案 | 当前代码 |
|--------------|----------|----------|
| §2.5 / §3 | 视口空闲 1500ms 合并、包装 setter 自动快照 | **未采用**。使用 **`checkpoint(label?)`** 在关键业务点推栈 + **`debounceMs`（默认 220ms）** 在 `snapshot` 变化时把 baseline 压栈 |
| §2.2 快照 | 未写 `tileSizes` | 快照 **含 `tileSizes`**，与持久化一致 |
| §5 Toast | 规划扁平 key | 使用 `t.segments.segmentCanvas*`；成功提示为 **`segmentCanvasUndoToast` / `segmentCanvasRedoToast`**，占位符 **`{action}`** |

### 15.2 Hook 行为摘要

- **`cloneSnapshot`**：深拷贝并**保留 `label`**。
- **`snapshotEquals` / `snapshotDataEquals`**：比较**忽略 `label`**，避免重复入栈。
- **`undo` / `redo`**：向对侧栈 `push` 当前快照时，若弹出项带 `label`，则**写入当前快照**，保证 **redo** 与**再次 undo** 的 `label` 与 Toast 语义一致。
- **`suspend`**：`persist` 未加载或画布 layout 同步暂停（如拖动中）时为 `true`，防抖不推栈。
- **`persistKey` 变化**：清空两栈（与 §8「切换场次/故事」一致）。

### 15.3 `checkpoint` 与内部 label 字符串

业务传入的 `label` 与 i18n `segmentCanvasHistoryLabel*` 映射一致（`SegmentCanvasTab` 内 `segmentCanvasUndoRedoHistoryLabel`）：

`create_node`、`reset_layout`、`remove_node`、`remove_ref_pad`、`add_edge`、`reconnect_edge`、`add_shots`、`confirm_ref_pads`、`drag`、`resize`。
