## 一、Rust 后端依赖

### 1.1 桌面框架与插件

| 依赖 | 版本 | 功能说明 | 在项目中的用途 |
|------|------|----------|----------------|
| **tauri** | 2 | Tauri 是一个轻量级桌面应用框架，使用 Rust 作为后端，Web 技术作为前端。相比 Electron，Tauri 打包体积小（~10MB vs ~150MB）、内存占用低、安全性更高。 | 作为整个桌面应用的壳，负责窗口管理、IPC 通信、文件系统访问、系统托盘等桌面能力。 |
| **tauri-build** | 2 | Tauri 的构建时依赖，用于编译时生成必要的绑定代码和资源。 | 在 `cargo build` 时处理 Tauri 特有的构建流程。 |
| **tauri-plugin-updater** | 2 | Tauri 官方更新插件，支持静默下载、增量更新、签名验证。 | 应用自动更新功能，检查新版本、下载更新包、验证签名后安装。 |
| **tauri-plugin-process** | 2 | Tauri 进程管理插件，提供进程重启、退出等能力。 | 应用重启（更新后）、优雅退出、子进程管理。 |
| **tauri-plugin-dialog** | 2 | Tauri 对话框插件，提供原生文件选择、消息框、确认框。 | 文件导入导出选择、操作确认提示、错误消息展示。 |
| **tauri-plugin-single-instance** | 2 | Tauri 单实例插件，确保应用只运行一个实例。 | 防止用户多次打开应用，第二次启动时聚焦到已有窗口。 |

## 四、Feature Flag 说明

Rust 后端通过 Cargo feature flag 控制可选依赖的编译：

| Feature Flag | 启用的依赖 | 说明 |
|--------------|-----------|------|
| `default` | 无 | 默认不包含任何可选依赖，最小化编译体积 |
| `local-ai-text-only` | candle-core, candle-transformers, candle-nn, hf-hub, tokenizers | 仅启用本地文本推理能力（Candle + Hugging Face） |
| `local-ai-whisper-inprocess` | whisper-rs, hound | 启用进程内 Whisper 语音识别（需 LLVM，仅开发/实验用） |
| `local-ai` | local-ai-text-only | 完整本地 AI 能力（文本推理走 Candle，语音识别走 whisper-cli 外挂） |
| `merge_shadow_audit` | 无 | 启用合并管线审计模式（shadow_l3 对照期审计） |

**编译示例**：

```bash
# 最小化编译（无本地 AI）
cargo build --release

# 启用本地 AI 文本推理
cargo build --release --features local-ai-text-only

# 启用完整本地 AI
cargo build --release --features local-ai
```

## 五、安全与许可证

### 5.1 安全考量

| 类别 | 措施 |
|------|------|
| **凭证存储** | 使用 aes-gcm 加密存储 API 密钥，不明文落盘 |
| **更新验证** | 使用 minisign-verify 验证更新包的 Ed25519 签名 |
| **传输安全** | reqwest 使用 native-tls，确保 HTTPS 证书链验证 |
| **依赖审计** | 定期检查依赖的安全公告，及时更新有漏洞的版本 |

### 5.2 许可证概览

所有依赖均采用开源许可证，主要包括：

| 许可证 | 代表依赖 | 说明 |
|--------|----------|------|
| **MIT** | serde, tokio, axum, react, vite | 最宽松，允许商业使用 |
| **Apache-2.0** | reqwest, rusqlite, three.js | 允许商业使用，需保留版权声明 |
| **ISC** | semver, once_cell | 类似 MIT，允许商业使用 |
| **BSD-2-Clause** | uuid | 允许商业使用，需保留版权声明 |
| **MPL-2.0** | webview2-com | 允许商业使用，修改部分需开源 |

> 注：具体依赖的许可证可能随版本变化，建议在发布前使用 `cargo license` 或 `license-checker` 工具进行完整扫描。

## 附录：依赖更新策略

1. **定期更新**：每月检查一次依赖更新，重点关注安全补丁
2. **锁定版本**：使用 `Cargo.lock` 和 `package-lock.json` 锁定精确版本
3. **测试验证**：更新后运行完整测试套件，确保无回归
4. **渐进升级**：大版本升级（如 React 19、Tauri 2）分阶段进行，先在分支验证
5. **安全优先**：安全相关的依赖（aes-gcm、sha2、minisign-verify）优先更新
