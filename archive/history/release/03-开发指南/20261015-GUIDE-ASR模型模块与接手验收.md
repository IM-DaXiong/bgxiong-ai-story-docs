## 1. 范围与当前可用性

本轮是语音转文字（ASR），不是文字转语音（TTS）。文本模型选择器保持独立；ASR A 与文本整理 B 可以分别选择。

Whisper 沿用独立 CLI adapter，描述位于 `runtimes/asr/whisper/module.json`。首发仅声明 CPU，命令明确传 `-ng` 禁用 GPU；不要把模型名称或显卡存在解释成 GPU 已验证。运行时不存在必须提示安装，不从 PATH 找替代程序。

Qwen3-ASR-1.7B、FireRedASR2-AED 已完成 Windows x64 CUDA 首发认证，`certifiedPlatforms` 包含 `windows-x64`，各自独立的哈希锁定 wheelhouse 与权重包已进入 `data/offline-drop/asr/`。认证范围严格限定为 RTX 4090、单条合成普通话样本、text/unit timing、认证 Sidecar 生命周期和断网依赖闭包；CPU、方言/噪声/长音频质量与其它显卡档位仍未认证。主项目允许零模块安装正常启动。

## 2. 合同与调用路径

合同权威为 `packages/app-contracts/v1/asr.json` 和 `asr.schema.json`；纯 Rust core 为 `src-tauri/crates/bgx-asr-core/`，生成器为 `bgx-contract-gen/src/asr.rs`。前端只导入 `ui/src/api/asr.generated.ts`，不得手写第二套 DTO。

操作选择只有：

- 默认：`{"kind":"default"}`。
- 显式：`{"kind":"explicit","modelConfigId":"已登记配置ID"}`。

输出要求使用 `timing: textOnly | segmentTimed | unitTimed`，可带 `language`；省略语言按合同中文处理，显式 `auto` 不得改写为中文。不支持的能力明确失败，禁止换引擎、估计时间戳或给结果补假时序。

应用入口统一经 `src-tauri/src/asr/service.rs`：

1. prepare 解析一次 default/explicit，冻结配置、模块、包身份、选项、能力、owner 与有效期。
2. execute_prepared 使用被冻结句柄；采集期间更改默认不改变进行中的操作。
3. release 等待受管资源收尾，不删除权重或用户配置。

2026-11-06逐字字幕修复：所有模型的单位文本通过宿主统一映射与覆盖校验。对齐器可省略没有独立发声时间的标点；宿主仅把正文已有的P类标点放到真实单位的展示文本，不补造时间、不改正文。实字/数字/符号不一致仍报invalidOutput，并在日志根留下完整结果与首差异。Qwen、FireRed及Whisper共用此规则。源代码/验收入口与边界见「文件级方案」（开源版未收录该内部文档或源码路径）；已接收2.0.3运行时和原ZIP/SHA保持不变，此次宿主修复不能通过覆盖已安装Python文件生效。

文件转写真实 IPC 是 `local_speech_recognition`，请求使用生成的判别联合：selection 分支含 selection/audioPath/outputRequirements；prepared 分支只含 preparedRef/audioPath。不能拿已准备句柄重新选模型。管理 IPC 位于 `commands/asr.rs`：list_engines、list_models、probe、set_default、set_display_order、prepare、release、runtime_instances、runtime_control、uninstall_preview、uninstall_execute；名称均有 `asr_` 前缀。probe 只返回就绪事实，不创建句柄；runtime_control 仅 stop/restart，启动在授权后的 prepare 进行，卸载走独立预览/执行。云凭据通过 owner-scoped 临时绑定注册，不进入纯合同、冻结对象和日志。

Creator/F1/MCP 使用同一目录中的 `asr.models.list`、`asr.preferences.get`、`asr.transcribe`、`asr.preferences.change.prepare`、`asr.runtime.control.prepare`；写操作走标准 `change.apply`，不建 F1 私有接口。Creator 转写只接授权 sourceRef，不开放任意文件系统路径。

## 3. 默认、排序与统一选择器

默认唯一权威是既有 `defaults.speechRecognitionModelId`。改默认采用字段 CAS；普通设置保存不能覆盖较新的默认。排序独立存于 `local_model_display_order.json` 的 speechRecognition 组，使用宿主下发 revision；拖动、改名、安装、卸载均不得自动改默认。

有 UI 的入口使用 `ui/src/domain/model-picker/pairs/TranscriptionModelPicker.tsx`；目录订阅在 `ui/src/domain/asr/useAsrCatalog.ts`，配置与默认控制在 `ui/src/components/asr/`，运行管理在 `ui/src/components/local-models/AsrRuntimePanel.tsx`。不要另做每页 selector 或在客户端计算 CAS 指纹。

已接收且配置有效的 Sidecar 未启动时，目录不报 `missingEnvironment`，模型仍可选择；`runtimeReady`/`inferenceReady` 保持实际 false，开始识别时由 prepare 启动。管理卡明确显示停机状态，重读有反馈，卸载预览先弹窗显示核验中，拿到宿主完整 fingerprint 后才允许确认。参见 「2026-10-16 续修」（开源版未收录该内部文档或源码路径）。

达芬奇等没有模型选择入口的操作发送 default。默认未设置、已删除或不可用时明确失败，不选列表第一项。Bridge 使用 `asrSelectionV1` feature 握手，旧协议应提示升级。

## 4. 新增独立模块

以 `runtimes/asr/qwen3-asr/` 或 `fireredasr2-aed/` 的结构为参考，但不要复制认证状态：

1. 建独立目录，提供 `module.json`、`manifest.json`、`UPSTREAM.lock.json`、`options.schema.json`、`requirements.lock.txt`、`engine.py`、`start-sidecar.ps1` 和 tests。engineId 是合同标识，不从文件夹名或文件扩展名猜测。
2. 描述声明真实 artifactRoles、requiredFor、输出时间能力、语言、设备和 maxInputMs。Qwen 的文本与 aligner 能力须区分；未装 aligner 不能承诺有时序输出。FireRed 不支持的 auto 语言不得静默映射。
3. 实现 Engine.prepare(request) 与 Engine.transcribe(path)，复用 `runtimes/asr/_shared/` 协议。模型框架只在独立 worker 中加载，共享 server 不写模型名称判断。
4. Sidecar 只监听 loopback；所有路由含 health 都认证。host 通过环境传 token/nonce，不能出现在参数、结果、日志里。端口冲突失败，不附着或终止外部 PID。
5. 每模块独立 .venv/依赖；禁止借用 TTS 或另一个 ASR 环境。probeOnly 不安装；provisionOffline 只用于新候选目录与完整本地 wheelhouse；runOnly 不联网补下载。
6. runtime-intake 完成实际接收后才发布 descriptor 和身份凭证。同修订不可原地替换已接收代码/环境。新增模型若遵循既有标准 transport，只增加模块及接收资料，不给业务消费者加厂牌分支。
7. 先测零安装、单独安装、组合安装、坏包、取消、超时、默认变更、故障收尾与卸载，再做真实离线推理和中文时序验收。

模型配置必须显式保存 `extraParams.asr` 中 engineId/moduleRevision/artifactBindings/optionsSchemaRef/optionsRevision/options/deviceProfile。普通扫描只提供候选，不能把 .bin 自动当 Whisper，也不能把每个 safetensors 分片登记为一个模型。

动态登记的唯一实现为 `asr/module_registration.rs`，由标准 `runtime_intake/adapters/asr.rs` 在可信接收完成后调用。发布新的兼容模块需要更新可信 requirements 数据，不需要修改 service/UI 引擎枚举；任意本地 descriptor 不构成安装授权。登记校验复用权威 ASR JSON schema 和共享 schema resolver，核对协议、精确引擎版本目录、包内引用与闭合选项定义。目录读取还比较登记副本和已接收包及其完整性凭证，损坏项单独不可用；登记记录或完整性凭证均不代表依赖已就绪或质量已认证。

## 5. 目录、接收与卸载

权重位于 `{app_data}/models/speech_recognition/`；运行时位于 `{app_data}/runtimes/asr/<engine>/<revision>/`。以实际 path service 为准，禁止写死本机盘符。主程序不捆绑 Torch 或模型权重。

管理操作不等同于加载全部模型。runtime snapshot 只报告已有实例及健康状态；停止/重启按实例身份和指纹提交。卸载必须先获取宿主预览，再提交相同 fingerprint。运行时卸载只移动目标运行修订和登记描述，保留权重、配置和默认。模型卸载传 modelConfigId，预览展示独占 targets 与共享 retainedTargets；仅独占权重移入 models/speech_recognition/.trash，删除该配置，保留共享文件、运行时和默认引用。恢复目录 recovery.json 保存配置快照及原路径映射；恢复时先核验原路径未被新文件占用，只恢复所移除配置，不能覆盖其它当前配置。仅删配置按钮不删权重。存在模型租约、终止失败或内容/引用变化时明确拒绝。

打包脚本为 `scripts/build-asr-offline-bundle.ps1`，必须提供 ModuleDir、ManagedPython、Wheelhouse、CandidateEnvironment、MainModelDir；Qwen 另传 AlignerModelDir，可选 OutputDir。wheelClosureComplete/certification/Windows 平台任一不合格都应失败；不得用空依赖锁生成“成功包”。生成器 `gen-asr-contracts --write/--check` 同时生成/校验 TS 与 `_shared/asr-contract.json={schema,constants}`；host build 和打包前检查都拒绝过期导出，不能手工维护镜像。构建器会在全新候选环境执行 `--no-index --require-hashes`、import/CUDA 探针和权重锁复核，全部通过后才原子发布归档与 sidecar。

## 6. 离线迁移与备份恢复

### Offline Drop 构建与投放

ASR 的投放清单和验收边界见 「ASR 离线交付说明」（开源版未收录该内部文档或源码路径）。发布构建产物放在 `dist/offline/asr/`，投放位置为 `data/offline-drop/asr/`（安装版对应实际 app_data 的 `offline-drop/asr/`）。不要把构建中的 `.staging`、下载缓存或未完成 wheelhouse 当成已发布包。

- `asr_launcher`：只有 module、共享协议代码及 receipt；不含模型或 wheelhouse。
- `asr_artifact`：每个引擎独立 wheelhouse、主模型分别成包；Qwen aligner 另包，可不安装。两类都携带真实 SHA-256、长度和 moduleRevision；artifact 还必须有 artifactRevision。均以 replace 安装到独立修订，禁止混用两引擎的依赖环境。
- 归档旁必须有构建器生成的同名 `.offline-bundle.json`。launcher 内嵌 runtimeManifest；上传树另写 `<runtimeId>-<version>.json`。CDN 对象相对目录由 `runtimes/cdn-object-layout.json` 唯一决定为 `asr/`，不得改为根目录平铺。
- 装配只复制已经存在且摘要、长度完全匹配的包，不下载未知模型，不造占位 URL/hash，不修改默认模型，不把 L1 文件存在当成 L2/L3/L4 合格。显式 ASR 装配找不到 sidecar/归档时失败并报告 NOT_RUN。

仓库根执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/assemble-offline-drop-upload.ps1 -AsrOnly
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-offline-drop-runtime-manifests.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check-offline-bundle-ssot.ps1
```

第一条只处理 ASR，不启动旧 TTS、Whisper 或 FFmpeg 下载；支持 `-AsrSourceRoot` 指向实际构建产物目录。重复装配相同字节是幂等操作；目标同名文件摘要不同则拒绝覆盖，须先核对版本和发布身份。不会自动删除投放目录已有的其它包。前两层验证不替代安装端 receipt 文件闭包检查、全断网建环境和真实中文推理；相应证据仍单独记录。

先关闭应用，并确认准确 app_data。下列路径参数是占位符，必须替换，禁止直接对未知目录执行：

```powershell
python scripts/migrations/20261015_migrate_asr_model_configs.py --app-data "<实际应用数据目录>" --dry-run
python scripts/migrations/20261015_migrate_asr_model_configs.py --app-data "<实际应用数据目录>" --apply
```

仅在该脚本 pending journal 指明未完成迁移时，经检查后使用同路径 `--recover`。脚本保留配置 ID/已有默认，不把排序当选择；只有唯一有效旧识别配置且默认空时才迁默认。旧已知 Whisper 迁为明确模块身份和 CPU deviceProfile；未知模型不能套用 Whisper。备份位于 app_data/backups，不移动权重，不改表结构。

本地完整备份恢复增强仅覆盖 ASR，详见 「备份恢复说明」（开源版未收录该内部文档或源码路径）。保留 ID、模块和 artifact 引用；跨机按托管相对路径重定位；缺包保持不可用；ID 内容冲突与不同默认显式失败。配置文件备份/journal、默认 CAS 和内存发布形成受控提交，失败恢复前态。账号中心导入仍保留本机 ASR 默认，不导入另一机器的默认 ID。进程崩溃留下 pending journal 时按文档核对真实提交状态，禁止盲删。

## 7. 接手验证命令与边界

平台归属按 SPEC §1：`src/asr` 是宿主编排与受管 I/O 实现，`crates/bgx-asr-core` 才是无文件/进程/网络依赖的纯核心。平台门禁只在 `platform-fs-exemptions.txt` 以 `=` 精确登记执行文件、PCM流、模块接收/备份等 I/O 文件，不豁免整个 `asr/`，因此纯选择/分段/状态逻辑新增 I/O 仍失败。核心 crate 在平台门禁中单独强制扫描，不能套用宿主登记；隐藏子进程、受管路径与模块隔离门禁继续独立适用。定向检查可运行 `scripts/check-platform-boundary.ps1 -AsrOnly`；这不代表其它历史模块或全仓门禁通过。

在仓库根运行：

```powershell
cargo run --manifest-path src-tauri/crates/bgx-contract-gen/Cargo.toml --bin gen-asr-contracts -- --check
cargo test --manifest-path src-tauri/crates/bgx-asr-core/Cargo.toml
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check-asr-engine-ssot.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-asr-host-isolated.ps1
python -m unittest discover -s scripts/tests -p test_asr_model_migration.py -v
```

修改 schema 后先运行同生成器 `--write`，再 `--check`；host build 会拒绝过期 TS。隔离 harness 编译生产 audio/chunking/process/artifacts/frozen/order/settings/backup 源码，但无关宿主端口使用测试 fixture；它验证真实文件操作、SQLite CAS 与子进程取消，不认证 FFmpeg、Tauri、真实模型或 GPU。不得把非零测试数替代相应 Gate 的实际证据。

统一最终验收由主代理执行实际 IPC 快照、受影响检查、host 编译、前端测试、Python sidecar 测试和安装版实跑。不要并行启动多个全仓 Cargo/check:affected 争锁；不要把旧听写保存链已通过当成本轮新链路已验收。

当前必须如实保留的环境边界：

- Windows x64 CUDA 离线闭包、真实权重、真实推理与 Sidecar 生命周期已通过；不能外推为 CPU 或所有显卡/驱动组合。
- 授权中文方言、混说、噪声和长音频标注语料仍缺，30 分钟监听与质量门仍为 NOT_RUN。
- 实际达芬奇与外部 MCP 客户端端到端操作仍需要对应宿主环境；未执行就是 NOT_RUN。
- 模块接收健康检查不等于模型能力验证；本轮认证证据必须同时引用依赖、实推和 Sidecar 报告。
- 最终构建与所有 Gate 结果以主代理最新台账为准。出现失败须记录命令、退出码、具体原因和下一步，不以文档完成宣告全部产品完成。

## 9. 常驻 Whisper 原生服务：构建、发布与验收脚本
