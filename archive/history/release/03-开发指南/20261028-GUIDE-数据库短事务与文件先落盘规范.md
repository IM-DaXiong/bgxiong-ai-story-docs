# 数据库短事务与文件先落盘规范

> **开源整理版**（2026-11-12）：已去除或改写私有路径、未公开端点、凭证示例，以及登录 / 认证 / 付费相关实现细节。若某节全部属于上述范围，将改为一句能力边界说明。


2026-10-28，用户明确的全仓开发硬规则：INV-DB-SHORT-TXN。适用于界面、Creator/F1/MCP、后台任务、运行时、媒体、导入导出、恢复与清理；高于旧PLAN/SPEC中相冲突的持锁安排。

## 生命周期

1. 通过短读取取得必要输入身份、版本和快照；释放Statement、游标、连接及读事务。
2. 在库外执行文件复制、编码/解码、校验/哈希、推理、网络、子进程与异步等待。文件先写完并关闭；需要耐久性时先完成同步落盘。
3. 成果就绪后借连接，开启短写事务。只进行必要的权限/归属/CAS检查、元数据更新、引用登记和共享回执记录；提交或回滚后立即释放。
4. 提交后发送通知、刷新视图或继续下一项耗时工作。禁止在事务里等待UI确认、模型、磁盘文件处理或另一异步任务。

“短连接”指每次借用的作用域短；不要求销毁既有连接池，也不以每次新建物理连接代替生命周期治理。读事务同样不能跨耗时操作；它可能阻碍检查点或形成旧快照。线程局部AmbientPlan必须在同一线程创建/提交/析构，禁止跨可迁移的await；仅固定线程而仍包住文件处理，同样违规。

## 文件与数据库无需全程大事务

优先保证用户继续操作。允许文件已落盘而数据库尚未登记、提交失败留下临时文件/孤儿成果，或待续办的中间状态；用既有任务、受管路径及清理引用规则定位，后续清理或显式续办。不得为避免这类残留长期占用DB。

允许残留不等于允许伪报成功、丢弃用户输入、绕过权限、错写项目、破坏结构约束或把未提交结果标为已保存。应记录真实阶段、成果位置和失败原因；涉及portrait_cache/story_media/visual_asset_media继续遵守既有孤儿引用登记规则。文件删除与慢清理也在事务外执行。

CAS冲突应按现有合同拒绝并保留成果/草稿。禁止为了消除锁错新增无限重试、放大超时、自动重跑昂贵操作或在另一个进程里继续占用同一数据库长事务。后台worker是避免阻塞UI的执行位置，不是持锁豁免。

## 自动保存与交互

布局/偏好等后台保存异步执行，失败只记可定位日志并保留当前内容及待保存事实，不周期性弹窗打断正常操作，不禁用/重新水合当前输入。后续正常保存机会可以保存最新状态，不新增无限重试循环。用户显式保存或业务提交失败须给清楚反馈；不可因关闭toast而伪称持久化成功。

后台刷新失败保留最后有效视图、错误状态及日志，不反复toast。没有可用内容时仍须显示可重试的页面错误，不展示伪成功空白数据。

## 验收与全仓执行

- 延迟/暂停真实路径的文件或异步阶段，用同一个数据库的另一独立连接执行无关业务写入，必须及时完成；这证明没有长期持有writer锁。
- 检查成功、异常、取消和提交失败之后，另一连接均能继续写入。真实文件残留按既有规则可追溯，不能以删除日志/样本使测试通过。
- 验证最终元数据与共享回执的短事务一致性；原有权限、恢复和事务回归保留。
- 日志记录数据库操作阶段与耗时，慢操作定位到具体owner；不能把所有storage故障都提示成生成结果无效。
- 新增和修改代码立即遵循。现存调用点按影响分阶段核查，不把本次窄修说成全仓已经完成迁移；先处理能阻断所有界面的已证实路径。
