# GUIDE：生图 / 生视频随机种子与可复现性

**状态**：审计结论（只读文档；不改产品代码）  
**类型**：GUIDE · 厂商 RNG seed 契约 + 本仓接线实态  
**范围**：本仓已接入的**云端生图 / 云端生视频**通道，以及**本地 ComfyUI** 生图/生视频工作流  
**不覆盖**：TTS、音乐 ACE-Step、故事「创意种子提取」、Pad/会话 hydrate 里的 `seed*` 命名（那些不是扩散 RNG）

---

## 0. 直接结论（给产品 / QA）

**不是。** 工作台里「同一条提示词再点一次生成」，**几乎所有云端图 / 视频都会不一样**。

原因叠了三层（缺一不可）：

| 层 | 含义 |
|----|------|
| **L1 官方 API** | 扩散模型靠 RNG seed。不传 seed（或传 `-1`）时，厂商每次抽新种子。即便固定 seed，多数官方只承诺「类似 / 相对稳定 / 极大概率」，**不保证像素级一致**。 |
| **L2 本仓接线** | 多数通道根本不把 `seed` 写进请求体；少数能读 `extra.seed`，但正常 submit 路径不会塞这个字段。 |
| **L3 工作台 UI** | 生图 / 生视频工作台**没有** seed 控件；`VideoSubmitPackagingGeneration` 也没有 `seed` 字段。用户无法「钉死种子再生成」。 |

本地 ComfyUI（见 §4）：`KSampler*` 与 `RandomNoise.noise_seed` 每次提交覆盖为墙钟毫秒 seed（INV-COMFY-SEED-RT）。工作台仍无钉死控件——**这是随机再点，不是可复现产品契约**。

**禁止**把「后端能解析 `extra.seed`」理解成「用户可以固定种子」。

---

## 1. 三层口径（读表时对照）

每模型表格四列含义：

| 列 | 含义 |
|----|------|
| **官方 seed** | `docs/api/` 或厂商文档是否声明 `seed` 参数；官方对「同 seed」的承诺原话 |
| **本仓是否发送** | Rust adapter 实际是否把 seed 写入 HTTP body |
| **工作台能否填** | 生图/生视频工作台是否有控件；submit SSOT 是否投影 seed |
| **同提示词再点** | 用户在本应用正常路径下再生成一次：几乎必不同 / 同 seed 时「类似」/ 本地可能碰巧接近 |

权威代码锚点：

- 生图 extra 合同字段：`src-tauri/src/open_platform/image_types.rs`（`ImageGenerateExtraV1.seed`）
- 生图 submit 投影：**不**投影 seed（`resolveImageGenSubmitExtra` 只走画幅/清晰度/负面/`promptExtend` 等）
- 视频打包：`src-tauri/src/open_platform/video_submit_packaging.rs`（无 seed）
- Clips 可选 seed（工作台用不了）：`src-tauri/src/clips/types.rs` → `video_submit.rs` 写入 `extra.seed`
- Comfy 随机：`src-tauri/src/comfyui/workflow/placeholders.rs` · `injector.rs`

## 4. 本地 ComfyUI（Flux2 / Ideogram4 / Krea2 / OmniGen2 / SenseNova / 自定义）

| 项 | 内容 |
|----|------|
| **通道** | `image_comfyui` / `video_comfyui`（`custom:<workflow>`） |
| **本仓 seed 来源** | 每次 `random_seed()` = Unix **毫秒**时间戳（非密码学 RNG） |
| **注入范围** | `injector` `apply_runtime_generation_seeds`：`RandomNoise.noise_seed`；`KSampler`→`seed`；`KSamplerAdvanced`→`noise_seed`；类名含 `KSampler` 的节点 → `noise_seed` 或 `seed`。标量直接覆盖；link 仅一跳改 `PrimitiveInt.value`（INV-COMFY-SEED-RT-01~03） |
| **不注入** | SeedVR2 / FlashVSR / 修脸（不走本 injector；超分有独立 UI seed，见 §5） |

| **工作台** | 无 seed 钉死控件 |
| **同提示词再点** | **不同**（每次新毫秒 seed，含 H3 / Flux / Ideogram / Krea 的 RandomNoise 图） |

## 7. 若产品要「可复现」（本 GUIDE 不做；另开 PLAN）

端到端需要同时满足：

1. 工作台 draft + 投影 + packaging / submit extra 写入 `seed`
2. 各 adapter 按官方范围发送（Seedance 2.0/2.5 须先对齐官方「是否支持」）
3. DashScope 等须处理 `prompt_extend`（改写会破坏「同提示词」前提）
4. ComfyUI：运行时已注入 `RandomNoise.noise_seed` 并回传任务 `generationSeed`；**UI 钉死控件仍另开 PLAN**
5. 文案只能写厂商口径（「类似 / 相对稳定 / 极大概率」），禁止承诺像素级一致
