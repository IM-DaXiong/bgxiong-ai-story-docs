## 1. 用户需求与范围冻结

统一的是 ASR/STT：音频 → 文字，首批 Whisper、Qwen3-ASR-1.7B、FireRedASR2-AED。上下文中“文本转语音”的口头用词，在本专题以这三款 ASR 和语音识别需求为准；不会把它们接到 TTS 合成通道。已有 TextModelPicker 负责文字整理，SpeechModelPicker 负责 TTS，新增 TranscriptionModelPicker 负责 ASR，三者复用现有 model-picker 交互内核，但模型、默认、参数和执行接口不混用。

“项目默认”沿用产品已有应用级 defaults.speechRecognitionModelId：全仓各故事、无故事工作台、F1、插件共享一个本机默认。不是增加 story_id 级设置，也不是新增仓库配置文件。今后若要求各故事不同默认，须另立 scope 合同，不由接手者自行推断。

首批迁移全部现役 ASR 消费者及已有云 ASR 可用入口。云 adapter 与本地 adapter 共用业务入口，但本轮本地默认字段只指向本地模型配置 ID。不增加其它云厂牌、不改整个文本或 TTS 引擎架构、不新增说话人分离，不承诺逐字实时流式；持续听写继续沿现有 VAD 分段协议。三模型包分别可装、可不装、可升级、可卸载；安装和卸载不影响应用冷启动及无关功能。

## 2. 单向依赖与每层所有者

业务 UI / IPC / Bridge / Gateway / Creator → AsrService → AsrEngineAdapter → 独立模型模块。
AsrService → bgx-asr-core；core 无 host、Tauri、SQLite、网络、进程、文件 I/O、模型名称及专属参数。
只有 composition/模块目录可以知道具体模块，业务只传选择意图、输入资源、输出要求。

- core：标准 DTO、能力匹配、选择规则、时间和引用结构校验；用现有合同生成器，不写同义 TS/Python 业务规则。
- host asr/：目录、精确选择、冻结、就绪、受管生命周期、音频预处理、分段、任务/日志/鉴权协调；不理解模型网络结构或厂牌报文。
- Whisper 模块：native CLI adapter，自己处理 GGML、DTW、特殊 token、简繁输出提示和专属解码参数。
- Qwen 模块：独立目录/venv/版本锁/engine.py，只在 Python 模块内使用 qwen_asr；Qwen 对齐器是该模块的按输出要求依赖。
- FireRed 模块：独立目录/venv/版本锁/engine.py，只用 FireRedASR2-AED；不与 Qwen 互 import。
- Sidecar transport/server/bootstrap：标准信封、进程、健康与取消机制；不把模型语义放共享层。
- 已有云 adapter：凭据、安全 HTTP、厂商报文、真实用量独立封装；不得静默把本地失败送云端。
- AI tasks、Creator requests/effects、settings、runtime intake、local model manager、媒体工具均保留现有持久化所有者；ASR 不新建另一套任务数据库或请求状态机。

## 3. 可插拔的确切含义

引擎实现源码模块独立；运行时、Python依赖、权重和可选子模型按模块隔离。主程序只带小合同、目录描述和通用接线，不在编译、安装器或启动时硬依赖 Torch/Qwen/FireRed 包。注册模块不等于模型已装，目录读取不启动推理。

首批 Whisper 的 native adapter 是主程序编译期模块，但其 CLI/权重是可选安装物。Qwen/FireRed 是标准 Sidecar 模块，模块实现不编译进主程序。标准 Sidecar 协议兼容的新实现只需登记可信描述和交付包；全新执行协议或 native ABI 必须开发 adapter，不能把任意 exe 放目录即声称可用。本期不实现任意 native DLL 热加载，不放宽现有模块来源/执行信任边界。

module descriptor 由相应模块目录提供，registry 校验唯一 engineId、协议版本、transportKey、artifact/option schema 和已认证平台，然后注册。运行中 accept/卸载通过维护 lease 切 active revision；未完成包、损坏描述或协议不兼容项显示不可用，不拖垮其它目录项。卸载只删除明确拥有的模块产物；保留用户模型配置及生成成果，失效引用可恢复或由用户显式清除。卸载选中的默认后原 ID 保留为不可用引用，除非用户明确清空/设新默认；不能选其它模型。

## 4. 默认、显式选择、排序及冻结

SelectionV1 闭合判别联合。modelConfigId 是目录提供的不透明配置引用：本地引用 local_model_configs.json 的 ID，已有云条目由凭据绑定投影成稳定目录引用，不往本地模型表登记云权重。旧云入口的临时凭据由 transport 登记 owner-scoped secret handle 后形成短期引用，绝不把 apiKey 传进 core/frozen/result。default 仍只允许本地引用，云条目不得写进 defaults.speechRecognitionModelId。

SelectionV1：

- {kind:"default"}：读取 defaults.speechRecognitionModelId。
- {kind:"explicit", modelConfigId:"配置ID"}：精确读该配置。

selection 省略只在入口 schema 明确约定时表示 default，由 transport 统一标准化一次。空字符串/未知 kind/多余字段拒绝。显式 ID 缺失、不支持语言/输出/平台、模块没装均直接失败；不能落回默认。默认空或已失效同样失败，不选首项，不扫文件，不按模型名排序猜测，不读另一个入口的 localStorage 最近使用。

拖动排序权威为既有 local_model_display_order.json 的 speechRecognition 列表。默认权威仍是 app_user_settings V4 的一个字段；没有新 asr_defaults.json、无重复数据库表。排序写严格核对组内 ID 闭集和 revision，原子替换，落盘成功才发布刷新；默认更新读取最新 settings 并只 patch 一个字段，以 CAS 防止覆盖并发保存的凭据/其它默认。排序和默认各有 revision，不能假装跨文件有一个事务；操作分别提交、分别给回执。

asr_list_models 每条 VM 至少给 modelConfigId、engineId（不透明标识）、displayName、displayOrder、isDefault、capabilities、readiness、issues；不就绪配置不从目录消失。默认徽章按已保存引用显示，不按第一项显示。管理页复用现有 LocalModelsConfigTab 拖动机制，提供设默认/清空默认，不复制另一套排序组件。设默认要求模型登记、结构、L1主模型和认证平台有效，不要求启动全部引擎；实际 L2/L3 缺项仍在开始前阻断。

操作 picker 默认是“使用项目默认（实际名称/未设置/不可用原因）”，可临时选具体模型，选择不自动写默认、不写全局 ASR last-used。保留无效显式项供用户理解，不因列表刷新切换。业务无 picker（Resolve/后台/外部请求未指定）提交 default。有 picker 提交当次意图，运行前由后端权威解析并冻结。前端展示推导不作为执行选择权威。

ResolvedAsrV1 至少包含 operationRef、modelConfigId、engineId、resolvedBy(default|explicit)、modelRevision、runtimeRevision、optionsRevision、capabilityRevision、artifactFingerprint、requiredArtifactRoles、有效期/所有者。实际路径只存在 host 内冻结对象，普通UI/日志引用不含凭据。冻结绑定主权重/分片/tokenizer/config/aligner及所需可选模块；不能只冻结 modelId 或目录 mtime。

有采集流程时：prepare(selection, outputRequirements) → preparedRef → 采集 → executePrepared(preparedRef,input)。preparedRef 是已有操作/会话下短期资源句柄，不是新持久任务，绑定 owner/window/request 和过期时间。无采集业务在 submit 内 resolveAndPrepare 一次。preparedRef 与 selection 不能在一个执行请求中同时重选。release、owner 关闭或过期撤销句柄并清本操作资源；取消只停止当前计算，不自动重试、不自动撤销整个 prepared 会话。持续听写与批次可继续持有冻结身份，由调用者明确决定是否继续或 release；终止确认失败则锁存 terminateFailed，句柄仍存在也不得再次执行。

会话、字幕批次、长音频所有段共用同一冻结对象；用户改默认只影响之后开始的操作。变更权重/active/options 或卸载正在使用的包需 maintenance；在途 busy 拒绝变更，用户显式取消并真实收尾后才可修改。未经维护外部改文件会得到 modelChanged，不自动重解析模型。重新启动同模块同冻结版本不叫换模，但能力/路径变化必须重新提交，不无声补跑。

## 5. 输入、输出与能力合同

所有公开 JSON camelCase；内部 Rust snake_case；tagged enum 用 rename_all_fields="camelCase"。schemas闭集 required/type/enum/range/reference；错误不靠字符串前缀还原。

AsrInputV1：现有已授权 input resource 或 host 验证后的文件引用。格式校验和统一转码得到16kHz/mono/PCM16 WAV；staged已规范化数据跳过重复处理。媒体大文件用stream或ffmpeg，不全文件base64/内存上传。caller保持原文件所有权；adapter只能处理 operation 目录内授权输入，不能自行读任意host路径。

OutputRequirementsV1：
- textOnly：完整文字，无强制时轴/aligner。
- segmentTimed：要求句/段真实时间，供字幕；不能拿片长当精准识别时间。
- unitTimed：要求字/词真实对齐，供精细字幕及精确需要的消费者。
language省略：产品默认 zh（简体产品偏好独立），language=auto：真实自动识别能力；模型不支持auto则unsupportedLanguage，不把auto改成zh。zh-Hant 输出控制与 yue 识别语言分开，不继续把香港地区一律视为普通话。

AsrResultV1 必填 requestRef、outcome(speech|noSpeech)、fullText、detectedLanguage（可null）、segments、units、timingLevel(none|segment|unit)、timingOrigin(native|forcedAlignment|none)、elapsedMs、resolvedEngine、warnings；confidence/各阶段用量只有厂商实际提供才填。segments包含id/text/startMs/endMs/unitIds；units包含id/text/startMs/endMs及可空confidence。所需时序缺失要报 unsupportedOutput 或 invalidOutput，不在adapter/host补比例时轴。
允许纯文本fullText非空而segments/units空；合法静音noSpeech+空正文为空结果，不触发LLM修复。业务可以按自身动作提示未识别到人声，但不能伪造成功稿。

时间统一u64整数毫秒，有限范围，单位只转换一次；start<end、时长范围及引用闭集合法，按原始音频全局时间轴。外部浮点秒在adapter用统一round规则转换，非法/越界报错，不max(0)静默修复。分段只有host一次加offset；adapter局部时间与chunk sample起点清楚标识。
标点不一定有unit timing；原生units与展示正文的结构引用保存，通用层不搜文本关键词或用substring猜人物/句意/合格。native/aligner provenance必填；已有字幕换行工具的按字数比例布局仅为后处理展示估算，不能改写源识别timingLevel，不作为unitTimed能力。

2026-11-06逐字展示文本收口：宿主 `bgx-asr-core::canonicalize_timed_text` 在结构/时间/引用合法后，只将原segment正文已有、原生单元省略的Unicode P类标点映射到所属/邻接真实单元的展示文本；单元内按原字符位置，段首挂首单元，其余边界挂前单元。不得改变正文、真实时间、ID、引用、confidence或timingOrigin，不赋予标点独立发声时间。映射全部成功才提交，重复处理不重复添加。实字、数字、其它符号、额外字符、全文与段文漂移仍明确拒绝，不进行归一化改词或删标点后宽松通过。所有unit结果在分块前、合并后与字幕投影复核同一覆盖合同；完整校验后才报告ASR completed。失败结果在既有日志根原子保存，遵守同一日志保留策略。

字幕消费者沿同一规范化结果生成逐字时间附件和SRT，附件中的unit展示文本保留标点；折行沿真实unit边界，不因展示标点添加独立时间、不再删标点比较。映射发生在局部分块时间偏移前，之后仅按既有单次偏移与ID命名空间合并。失败不得以段时间或按字数插值冒充逐字时间。

CapabilitiesV1 是当前“模型+依赖+平台”的事实：text、segmentTiming、unitTiming、autoLanguage、supportedLanguages、scriptControl、maxInputMs（可null，不与产品整段时长上限混淆）、deviceProfiles、nativeStreaming。Qwen不安装aligner时text仍可用，timed能力为false；FireRed缺Punc不砍基础识别，缺LID不自造detectedLanguage。没有验证的平台unknown/unverified，不写supported。无法满足要求直接提示安装该依赖或选其它模型，由用户显式决定。

## 6. 音频分段与取消

host根据adapter公布的maxInputMs生成非重叠sample frame覆盖区间；优先VAD边界，超过单段限的连续语音按限切分，区间不得漏/重。FireRed首发maxInputMs=60000，写在该模块描述，core/UI不重复数字。VAD是质量优化，不是基础识别必需。长音频分段属于引擎技术能力适配，不设客户端/页面/人工次数上限。结果按段序拼接，不在自由模型文本里搜词去重；必要quality问题用样本实测决定该模块认证，不靠运行时语义拒收。

复用现有受控 child runner并移入asr域。OperationLease贯穿排队、prepare、推理、取消、worker收尾、文件清理。2026-10-15 实施修订：执行采用一个可空总预算 timeout 为权威，排队、身份核验、标准化、切片和计算都消耗同一预算；进入下一阶段必须扣减已耗时，不能拿锁或启动子进程时重置。没有两个用户可配置超时，也没有独立队列预算。等待必须同时响应取消与剩余 deadline；终止后的真实 kill/wait 属于安全收尾，不能因预算到期跳过。prepare 自身启动/健康检查另受受管启动策略约束，不冒充 execute 的已消费预算。调用future drop仍由owner task持锁清理。不同sidecar实例有独立状态，必要GPU资源协调复用既有资源所有者，不在ASR引入全局跨厂商降级队列。
标准Sidecar持久worker缓存一个已冻结模型；服务进程负责health/请求/取消，实际计算在其拥有的worker进程。HTTP取消ACK只有在worker停止计算并wait后才成功；单纯断开HTTP或tokio timeout不算结束。取消可释放计算 worker，但不改变 host preparedRef 的冻结身份与生命周期；后续明确执行仍须验证同一冻结身份，按受管协议准备该模型，不能自动重试已取消的输入或换模。无法确认退出则terminateFailed锁存，禁止下一段/卸载/重用，显示人工处理指引。只终止拥有且身份匹配的PID，不因端口被占杀陌生进程。

## 7. Sidecar协议、隔离与就绪

协议来自app-contracts：GET /health；POST /v1/asr/prepare；POST /v1/asr/transcribe；POST /v1/asr/cancel；POST /v1/asr/release。
这些只是本机进程协议，不另造用户AI任务系统；requestRef关联既有operation/ai_task/Creator request。request ID幂等和重复取消语义测试；只重查状态，不重复执行。

health：schemaVersion、instanceRef、ownedProcessNonce、pid、engineId、moduleRevision、ready、activeModelFingerprint、capabilities、deviceFacts、workerState、activeRequestRef；缺字段/身份不符不可复用，HTTP200不等于ready。Sidecar只绑定127.0.0.1，随机token由受管进程传入；路径绑定冻结artifact/input允许集合；健康/日志不回密钥；不接受远端 arbitrary shell/任意Python执行。
engineId是描述身份，不成为host厂牌分支；model-specific options通过模块闭合option schema验证，业务request无no_speech_thold/vLLM/beam_size等字段。专属选项只在设置模块详情中配置，提交冻结后不可悄悄修改。

安装/probe/启动明确三模式：
- provisionOffline：用户已明确选择安装，候选slot中离线建venv，仅wheelhouse完整闭包，不联网。
- probeOnly：真实L1/L2事实与所需依赖读取，不安装，不加载全部大模型。
- runOnly：使用已准备好的环境，启动/加载被选模块；缺环境立即报missingEnvironment。
现有runtime intake passive模式与此对齐，不能“健康检查”偷偷pip/download。共用托管Python可共享解释器，不共享venv/site-packages/Torch或模型cache。

L1文件/摘要/分片/许可；L2真实解释器import/ABI/device探针；L3进程/协议/模型/能力身份；L4真实中文文字/时间戳成果。四层分别显示installed/runtimeReady/inferenceReady/verified；过去L4证据绑定环境与artifact指纹，变更即失效。认证ready以实际要求为准，用户不装不被列为全项目缺项。

## 8. 平台/上游冻结与开箱约束

## 10. 持久化、迁移与卸载

复用local_model_configs.json、display_order和app_user_settings V4。ASR包元数据在 modelType=speech_recognition 配置的 extraParams.asr 命名空间闭合存储：engineId、moduleRevision、artifactBindings、optionsSchemaRef/optionsRevision、deviceProfile 与 module-owned options；默认引用仍为配置ID。modelPath允许模块声明的主文件/目录；文件类型与分片完整性由模块验证，不在manager统一*.bin假设。

离线迁移先备份配置和对应settings，dry-run、幂等、失败还原，已知旧Whisper配置写显式引擎。不启用每次启动猜*.bin回退。旧默认原样保留；旧默认未设且唯一个已知合法ASR配置可一次迁入默认，多个候选保持未设置并人话提示。未来新增模块不自动设默认。用户原权重路径/UUID/文件名不重命名。

配置持久化先成功后发布内存与事件；默认和排序不通过整份旧React settings覆盖最新记录。云账户同步继续排除本机模型引用；完整本地备份保留引用，异机恢复不可用而非自动换模。没有新增SQLite表，本专题无需table_registry新项；如实施者要新增表，须修订本计划而非暗加程序ALTER。

受管版本根按模块隔离；共享Python卸载不能删除其它模块正引用解释器；卸载检测活跃lease和引用，删目标前校验实际根及拥有权，保留成果和配置。任意外部误删会在probe/start显式反馈，不使应用崩溃或静默吞错。

## 12. 接手防漂移补充：标准动作边界

对外“一个接口”指一个 AsrService 业务权威而非每个场景都挤进一个万能IPC；参数模型只有一套，传输可以有标准管理/执行方法。

统一 ASR 业务边界由 service/catalog/preferences/management 等单一所有者提供，不要求所有方法放在同一 Rust impl：catalog、probe(selection,outputRequirements)、prepare(selection,outputRequirements,ownerContext)、executePrepared(preparedRef,input,executionContext)、release(preparedRef,ownerContext)、setDefault、setDisplayOrder、runtimeInstances、runtimeControl、uninstallPreview、uninstallExecute。

实际 transport 合同如下：

- asr_list_models 当前接受 request={}，返回 catalogV1；当前完整投影 nextCursor=null，不截断结果。后续若实现分页须同时增加真实 cursor 接收与续办，不能只让 UI 猜页。
- asr_probe 复用 prepareRequestV1（selection、outputRequirements），返回 readinessV1（installed/runtimeReady/inferenceReady/verified/issues），不分配 preparedRef、不改默认、不启动或加载 Sidecar 大模型。Whisper 可以执行受控轻量 CLI 帮助探针。已有 Sidecar health 只提供已有实例事实；probe 不等于一次完整独立环境 L2/L3/L4 认证。
- setDefaultRequestV1 是 kind=setDefault+modelConfigId+expectedRevision 或 kind=clearDefault+expectedRevision；setDisplayOrderRequestV1 为 orderedModelConfigIds+expectedRevision；两者返回 changeReceiptV1。
- runtimeControlRequestV1 仅允许 action=stop|restart，必填 instanceRef/expectedFingerprint；返回已有实例快照数组，不伪造 changeReceipt。无 start/uninstall 动作，启动属于授权后的 prepare。
- asr_uninstall_preview 的 runtime 分支接 engineId/moduleRevision；model 分支接 modelConfigId，由后端配置解析模块身份。返回 uninstallPreviewV1（engineId/moduleRevision/targets/retainedTargets/fingerprint/busy，可选 modelConfigId）。asr_uninstall_execute 原样接该预览并重新校验文件与全部配置引用指纹。runtime 分支只移除运行时；model 分支只移除该配置和独占权重，共享路径列入 retainedTargets 保留，两者都保留默认引用及生成成果。回执含 recoveryPath 与 retainedTargets；模型恢复目录包含配置快照和路径映射。准备阶段即持有模型租约，维护不能穿过 resolve/prepare 尚未发布的空隙。仅删配置仍是独立操作，不隐式删除权重。不得让 UI 自己计算指纹或把卸载伪装成 stop。
default清空是明确clearDefault动作，不用空字符串冒充有效ID；request内部不存在同一字段两种别名。metadata-only resolve不启动进程。

prepare 在执行授权下冻结身份：Sidecar 可 runOnly 启动并加载所选模型；native Whisper 冻结 CLI/模型并检查运行前提，实际 CLI 加载发生于 execute，不虚报已常驻加载。prepare 不安装环境。probe 不创建 preparedRef、不修改 active/default。public transcribe(selection,input,outputRequirements) 是 prepare+executePrepared+release 的一次 host 编排，所有 consumer 不能重实现。
default/排序返回 revision+effectRef，实例快照携带宿主 fingerprint，卸载返回 recoveryPath；前端不得自己计算 CAS 指纹。
执行调用由 host 传 owner/preparedRef，冻结对象携带 operationRef，SpeechExecContext 携带 cancel/timeout；现有 aiTaskScope 经 task-local capture/scope_future 贯穿 owned task。timeout 是 §6 定义的单总预算，不声明已实现独立排队 deadline/计算 deadline。scope 在入口决定，adapter 不独自插 AI 任务或绕过权限。

profile候选认证的实施产物必须给唯一完整锁：Python发行版本/ABI、Torch+torchaudio版本及CUDA族、上游commit、全部传递wheel版本/hash、权重revision/文件hash、认证设备/样品。AS003使用隔离实验env，不能声称未来正式module launcher已实现；其结果作为AS030/AS033正式包输入。失败只能补模块兼容性证据，不能绕过G4/G9。

Sidecar的runtimeReady可未载大模型，prepare到inferenceReady后health.activeModelFingerprint 必须等于冻结对象 artifactFingerprint，health.activeRequestRef 对应 operationRef；指纹不等于 preparedRef 字符串。text/segment/unit能力是requiredArtifacts子集和认证事实；不能只有“这个引擎理论支持”一个布尔值。当前 verified 不因健康成功自动置 true。

模型卸载预览返回 owned target 列表、engineId/moduleRevision、busy 与指纹；execute重新核对，只移动预览相同且被本模块拥有的运行时路径到受管 .trash，回执给 recoveryPath。身份变化重预览，半失败如实返回并重新probe；不自动清默认、删除权重或模型配置。新装模块/权重只有经过intake accepted注册才发布目录刷新，不凭文件名自动认成其它模型。

## 13. 单模型常驻、显卡准入与准备进度（PLAN 20261016 v2.0）

- 全进程同一时间只常驻一个本地识别模型。纯核心 `bgx_asr_core::residency` 做全部决策（代际、pin、等待者计为 pin、旧模型确认退出后才加载新模型、`terminateFailed` 保留所有权），宿主 `asr/resident_manager.rs` 只执行。
- 加载身份 = 引擎、模块修订、运行时内容指纹、全部制品角色、选项、设备与完整 `outputRequirements`；窗口、operation、目录不进入身份。
- 操作只持有 pin（`asr/adapters/resident_ops.rs`）；`release` 只放 pin，模型保留到空闲 TTL（`residentIdleTtlMs`）、被替换、仲裁、显式停止或退出。取消/超时/失败杀进程树并使该代际失效，下一次显式 prepare 重新加载，不自动重载。
- 传输：Sidecar v2（`prepare/transcribe/cancel/release/health`，`residentRef` + `executionRef` + `executionSeq` 高水位）；Whisper 为常驻原生本地识别服务（本机回环；开源版已省略其内部核验方式）。逐段 CLI 已退役（`native-whisper-cli` 不得出现）。
- 显卡：`asr` 是 `local-gpu-occupancy.json` 合同种类，Rust/TS 枚举均由生成器产出；CUDA 加载前先做准入预留（token 叠加到所有快照）；CPU 与云端识别不占显卡。
- 准备进度：事件 `asr-prepare-progress`，阶段 `waitingResource/verifying/loading/ready/stopping/failed`，总时限 `prepareTimeoutMs` 由宿主持有；按 `correlationRef`（仅限所属窗口）取消与查询快照。听写以会话 `operationId` 作为 `correlationRef`。
- 指纹：内容哈希按元数据签名复用，按路径单飞，容量 `fingerprintCacheMaxEntries`（LRU）。
